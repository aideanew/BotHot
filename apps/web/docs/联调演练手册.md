# 真实态联调演练手册（C-T6）

> 面向对象：零上下文的新成员（前端/后端/测试均可）。
> 目标：按本手册独立完成一次 **mock 态 → 真实态** 的切换演练，并掌握常见故障排查。
> 契约基准：`.docs/03_solution/interfaces/API接口文档.md` v0.3e（含 §五 c/d/e 补登）。SSE 流式协议细节**尚未定稿**，以 A 的变更单为准。

---

## 一、前置条件核对

| 项 | 要求 | 核对方式 |
|---|---|---|
| Node/pnpm | corepack 可用 | `corepack pnpm --version` 输出 12.x |
| 依赖已装 | frontend/node_modules 存在 | `corepack pnpm install`（缺则执行） |
| 后端 8000 | backend 服务运行中 | `curl http://localhost:3300/api/v1/system/health` 返回信封 |
| Docker（如后端走容器） | 容器编排已起 | A 侧确认；前端不需要 Docker |

> 前端**只依赖**后端 8000 端口可达；是否容器化是 backend/Docker 侧的事。

## 二、起服步骤（mock 态回归基线）

```bash
cd frontend
corepack pnpm build          # 构建产物（NEXT_PUBLIC_* 为构建期内联）
corepack pnpm test:e2e       # mock 主干 8 用例应全绿（baseline）
PORT=3200 corepack pnpm start
```

- 打开 `http://localhost:3200`，页脚/顶栏徽标显示 **“演示数据”** = mock 态。
- mock 态登录用 localStorage 标记（`bothot_mock_login`），不经过后端。

## 三、切换到真实态（联调窗口开启后）

**关键认知**：`NEXT_PUBLIC_API_MOCK` 是**构建期**变量——改完必须**重新 build + 重启**，仅重启不生效。

```bash
# 1. 停掉现有前端进程（端口铁律：3200 清零）
netstat -ano | findstr :3200        # 找 PID
taskkill /PID <pid> /F              # Windows；循环直至端口清零

# 2. 真实态构建（核心开关）
set NEXT_PUBLIC_API_MOCK=false      # Windows CMD
# export NEXT_PUBLIC_API_MOCK=false # Git Bash / Linux

corepack pnpm build
set PORT=3200 && corepack pnpm start
```

- 页面徽标显示 **“真实后端”** = 切换成功。
- 登录点击“使用主平台账号登录”→ 整页跳转 `/api/v1/auth/login` → 主平台 authorize → callback 回落 → 首页显示真实昵称。

## 四、逐端点期望信封（对照 v0.3e）

统一信封：`{code, message, data, requestId}`；`code=0` 为成功。浏览器 DevTools → Network 核对。

| 端点 | 方法 | 期望 data（成功） | 主要错误码 |
|---|---|---|---|
| `/api/v1/auth/me` | GET | `{sub, email, nickname, tier, wallet}` | 10001（401） |
| `/api/v1/auth/login` | GET | **302 跳主平台**（无信封） | — |
| `/api/v1/auth/logout` | POST | `data: null` | 10001 |
| `/api/v1/spaces` | GET | `{items: [{id, name, description, docCount, updatedAt}]}` | 10001 |
| `/api/v1/spaces/{id}` | GET | `{id, name, description, docCount, createdAt, updatedAt, stats:{docs, chunks}}` | 10001 / 30004 |
| `/api/v1/spaces/{id}/docs` | GET | `{items: [{id, title, source, status, updatedAt}]}`，status ∈ pending\|ready\|failed | 10001 |
| `/api/v1/chat/ask` | POST | 流式 SSE 或 JSON 信封 `{content, citations}`（**协议待 A 变更单**） | 10001 / 30001 / 30002 / 50002 |

### v0.3e 联调注意（重要）

1. **`description` 恒空串、`stats.chunks` 暂返 0**（v0.3c：数据源在 LangBot 侧，B-T9 接线定稿）——联调核对时**勿对二者做非空断言**，UI 显示“暂无简介”/0 分块属预期，不是 bug；
2. `30004` 已改登记名 `RESOURCE_NOT_FOUND`（通用 404）；无效空间 id 前端仍渲染“未找到该知识空间”空态；
3. `/api/v1/resolve`、`/api/v1/extract`（v0.3d/e 新增）**本版前端未接线**（属链接入库链路，后续任务卡），联调核对清单暂不覆盖；
4. 未登录访问受保护接口 → 后端 401 + `10001`，前端自动跳回首页引导卡（不是故障）。

## 五、mock 错误注入失效说明

- mock 态有两处**仅 mock 生效**的钩子，真实态下**自然失效**：
  1. 登录标记：`localStorage["bothot_mock_login"]="1"`——真实态走 HttpOnly cookie，前端不读写 token；
  2. 错误注入：提问含 **“触发错误”** 时首轮抛 `30002`、重试放行（sessionStorage 标记 `bothot_mock_ask_fail`）——真实态该词无任何作用，错误只能由后端真实返回；
- 真实态想复现错误态：等后端真实返回对应错误码（如停 LangBot 让 `/chat/ask` 返 30002），前端气泡文案与重试按钮行为一致。

## 六、常见故障排查

### 1. 真实态请求 404 / 打到 mock

- 现象：Network 里 `/api/v1/*` 返回 `{"detail":"Not Found"}`（框架默认 404）。
- 排查顺序：① 是否**重新 build**（只重启不重 build，环境变量不生效）；② 请求 URL 是否带了 v1 前缀（前端统一 `/api/v1/...`，rewrites 原样透传）；③ 后端该端点是否真的已部署（`curl http://localhost:3300/api/v1/...` 直连后端核对）。

### 2. rewrites 代理不通（前端 500 / ECONNREFUSED）

- 现象：`curl localhost:3200/api/v1/system/health` 返回 500，但直连 8000 正常。
- 原因：后端未运行，或 `BACKEND_ORIGIN` 指错。
- 处理：起后端；容器环境确认编排里传了 `BACKEND_ORIGIN=http://backend:3300`（本地 dev 默认 `http://localhost:3300`，不用传）。**后端下线时代理返 500 属预期**，可反向证明代理在转发。

### 3. 登录后仍显示未登录（cookie 问题）

- 现象：callback 回落首页后仍渲染引导卡。
- 排查：① DevTools → Application → Cookies，确认回调域下有 HttpOnly 会话 cookie；② cookie 域与前端域不一致（跨子域）时需后端设置正确 SameSite/Domain；③ 前端**不会**读写 token，不要查 localStorage。

### 4. SSE 回答无流式效果 / 一次性出全文

- 现象：回答整段出现（JSON 回退路径）。
- 说明：当前契约未定稿流式协议，后端可能先以 JSON 信封返回——属预期，前端两条路径都支持；A 变更单定稿后再核分片行为。

### 5. `pnpm` 命令不存在

- 本机 pnpm 经 corepack 代理：统一用 `corepack pnpm <cmd>`；CI/他人机器若 pnpm 在 PATH，直接 `pnpm` 等价。

### 6. e2e 复跑失败：端口占用

- Playwright webServer 配置 `reuseExistingServer: true`：3200 有残留进程时会直接复用**该进程的构建版本**。复跑前先按端口铁律清零，或确认残留服务是新构建的 mock 态。
