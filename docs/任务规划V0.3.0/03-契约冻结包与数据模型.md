## 2. ② Errors 契约

见 `contracts/errors.collection.json`（11 条失败路径 → 既有码位）。要点：
- 不新增码位（N-06）。
- 发现失败不暴露给终端用户，只进管理端面板与告警；入库失败经 JobItem.error 展示。
- `lastError` 与日志**不得**包含凭据、完整上游响应体（防泄露）。
- 被移除的失败路径：长链入库 500（`MultipleResultsFound`），回归测试锚定在 STEP-02。

## 3. ③ Identity 契约（采集域权限边界）

| 角色（`roles.py:29`） | 订阅/来源/Job | 管理端采集接口 | 越权禁止 |
|---|---|---|---|
| user | 仅自己空间 | ✗（403/10004） | 不得读他人订阅、不得看渠道凭据就绪原因以外信息 |
| operator | 自己空间 + 管理端只读与 Job 取消/重试 | ✓ | 不得改引擎密钥（`admin.py:342` 需 admin） |
| admin | 全部 | ✓ | — |

- 用户 ID：`users.id` String(36) UUID；身份锚 `users.sub`（REQ-F-007）。
- 后台任务（scheduler/worker）以系统身份运行，**不得**经 HTTP 路径；写入归属沿 `SourceSubscription.user_id`。
- 本轮不新增角色、不改 session/JWT 声明。

## 5. ⑤ Events 契约

采集域没有跨进程 outbox（outbox 属推送域 `push_events`）。本轮只冻结**进程内结构化事件**（日志字段 + 指标标签），
定义见 schema `$defs.CollectionEvent`：

| 事件 | 触发 | 载荷 | 幂等键 | 去重 |
|---|---|---|---|---|
| `discovery.page_all_skipped` | 一页 `skipped==rows>0` | source_id, channel, count | `{source_id}:{channel}:{yyyymmdd}:{page}` | 告警一天一次 |
| `discovery.id_fallback` | 行缺 id 以 canonical key 兜底 | 同上 | 同上 | 仅 WARNING 日志 + 计数 |
| `discovery.failed` | provider 抛 `DiscoveryFailedError` | channel, reason(脱敏) | 无 | 现有告警路径 |
| `manifest.enqueued/ingested/failed/stale_reverted` | STEP-04 状态迁移 | manifest_id, job_id | manifest_id+目标状态 | 状态机天然幂等 |

指标名（STEP-05）：`bothot_discovery_calls_total{channel,outcome}`、`bothot_manifest_rows_total{channel,result}`、`bothot_discovery_all_skipped_pages_total{channel}`。

## 8. 数据模型基线（采集域）

### 8.1 现有实体（`entities.py`，4afaedd）

| 表 | 关键字段 | 约束 | 问题 |
|---|---|---|---|
| `sources` | `type`、`external_id`（biz/锚）、`url` | `uq_source_type_external(type, external_id)`（`entities.py:67`） | 只存一种标识（F-15 相关，STEP-08） |
