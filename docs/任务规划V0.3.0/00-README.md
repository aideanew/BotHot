# BotHot 剩余任务规划 V0.2.1

## 一句话结论（每条可追溯到 evidence/）

1. **上一步（STEP-00）判「部分完成」成立，但它对唯一失败用例的根因判断是错的。**
   `test_event_delivery_failure_no_reclaim` 在 STEP-00 把 webhook 改指 `127.0.0.1:1` 之后**仍然失败**
   （本机连库全量：`1 failed, 1008 passed, 5 skipped`，`evidence/pytest_full_pg_4afaedd.txt`）。
   真实根因：`webhook.py:33` 的 `httpx.AsyncClient` 默认 `trust_env=True`，进程环境里存在 http/https 代理时，
   发往 `127.0.0.1:1` 的请求被代理接走并回 **HTTP 404** ⇒ `retryable=False`（`webhook.py:46` 只对 ≥500 判可重试）
   ⇒ 不推进 `retry_count`。清掉代理变量后 11/11 通过（`evidence/proxy_rootcause_4afaedd.txt` §C/§D）。
   ⇒ 「端口被 2xx 服务占用」只是**同族的另一种**触发方式，不是本机失败的原因；修复必须针对「测试出站受环境代理影响」。
2. **采集链路 4 个 P0 在最新代码上全部原样复现**（`apps/api/app/**` 自 61739f0 起零改动；`evidence/probes_4afaedd.txt`）：
   长链键坍缩为 `"s"`（冒名）、`LIKE '%s%'` 多源崩溃、清单键 ≠ 资产键（重复入列）、4 家付费源行无 id（零入库且静默）。
3. **测试“绿”掩盖了采集核心**：4 家付费 provider 覆盖率 16%–22%，`article_detail_fallback.py` 0%，
   而全量覆盖率 79%（`evidence/pytest_full_pg_4afaedd.txt`）。本轮“完成测试”的口径必须按模块计，而不是看总数。
4. **7 个人工裁决项仍未裁**（D-V2-01…07 在 V0.2.0 中均为“建议”，仓库无裁决记录）。其中 D-V2-01（文章键格式）是
   STEP-02/03/04 的共同前置，属 BLOCKING；本包对它给出 A/B 条件方案与共同部分，不擅自假设。
