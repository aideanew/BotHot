### 1.2 项目核心问题复述

BotHot 要把公众号（及 RSS）文章**按订阅自动、增量、去重地**采集入知识库，供 RAG 问答与热点/推送消费。
当前「自动采集」主路径在正确性上不成立：发现阶段对 4 家付费源产出为零且无告警；入库阶段长链文章互相冒名、
多源时崩溃；增量阶段已入库文章被反复入列。本轮要解决的就是这条主路径的正确性，并用测试把它钉住。

- 用户：订阅者（space owner，role=user/operator）——创建订阅、看入库结果。
- 管理端：admin——看发现渠道就绪度、Job、来源（`api/v1/admin.py:216-648`）。
- 系统边界：上游 = RedFox / Dajiala / JustOneAPI / TikHub / Wellbyte / RSS 与 mp.weixin.qq.com 页面；下游 = LangBot 知识库。
  不在本轮：推送域（G-19/G-21）、热点算法、SSO、前端新页面（仅 STEP-05 可选只读面板，降为 COULD）。

### 4.2 D-V2-01 条件方案

| | 方案 A（推荐） | 方案 B |
|---|---|---|
| 键形 | `b:{biz}:{mid}:{idx}` / `s:{token}` / `h:{sha256(规范URL)[:32]}` | `{biz}_{mid}_{idx}` / `{token}` / `{sha256[:32]}` |
| 键空间相交 | 不相交（前缀区分） | 可能相交（token 与 sha 均可能为 32 位 hex 形） |
| 存量兼容 | 旧短链键（裸 token）需回填为 `s:` 前缀 | 短链键不变，回填量更小 |
| 列长 | ≤ 2+32+1+12+1+2 < 128 | < 128 |
| 额外工作 | 回填脚本改短链键 | 必须加碰撞检测与告警 |

- **共同部分（可先行，不受裁决影响）**：`parse_wechat_url()`（解析 `__biz/biz/mid/idx/sn/短链 token`）、`_biz_from_url` 读 `__biz`、删除 `LIKE '%{key}%'` 兜底、全部 `.limit(1)`/唯一键查询、单字符片段禁止、先红测试 M-01/M-02（断言「键不同」「不崩溃」，不断言键的字面格式）。
- **分叉点**：`canonical_article_key()` 的返回格式、回填脚本、`ShortLinkMap.article_key` 写入值。
- **需人裁决的变量**：前缀与否、存量短链键是否改写。

## 6. 5W1H 与钢人论证（关键判断）

### 6.1 判断：本轮应先修正确性（STEP-02/03/04），而不是先做按源路由（STEP-08）

- **What**：4 个 P0 都在主路径上，路由是 P1 结构缺口。
- **Why**：路由修好后若键仍错，选对的渠道照样零入库/冒名；反之键修好后单渠道 RedFox 即可正确运行。
- **Where/When**：kb.py / manifest.py / subscription.py；必须先于任何生产回填。
- **Who**：Agent-API（kb/manifest/subscription）、Agent-Data（迁移）、Agent-Guard（测试门）。
- **How**：先红 → 契约 → 实现 → 探针转正 → 模块覆盖率门。
- **What if**：若 U-01 证实 RedFox 只给短链，P0-1 主路径影响缩小，但 P0-1b 崩溃仍在 ⇒ 顺序不变。
- **支持**：P-1…P-4 全部可复现；路由改造（D-V2-04）未裁。
- **反对**：运营若当前只用付费源，P0-3（零入库）比 P0-1 更痛 ⇒ 已把 STEP-03 设为与 STEP-02 并行，而非排在其后。
- **判定**：已确认（顺序依据为可复现缺陷 + 裁决状态）。

### 6.2 判断：「完成测试」以模块覆盖率 + E2E + 探针转正为口径，而不是总通过数

- 支持：总覆盖 79% 时付费 provider 仅 16–22%（F-12），总数掩盖缺口。
- 反对：覆盖率可被无断言用例刷高 ⇒ 要求每个契约测试含行级断言（`_map_row` 非 None + 时间 aware），并保留 G-23「断言须对旧实现敏感」的变异反证要求。
- 判定：已确认。
