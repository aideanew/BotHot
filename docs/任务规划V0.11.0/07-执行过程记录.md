## 4. 独立验证（防自证循环，本会话不判自己通过）
交只读子智能体按"只看 diff + 命令输出"复判，断言清单：
1. `HEAD == origin/main == bad10d3` 且 `0 0`；
2. 快进前"入站 ∩ 在途 = 0"是否真实（决定 `--ff-only` 是否安全）；
3. V0.10.0 的合计是否真为 183 / 28.25（按其表列，不按位置硬取）；
4. V0.10.0 前端证据件是否真的含 `/workspace/` 路径（本版核心论断的唯一支点）；
5. 本机 `node_modules`/`pnpm`/`gitleaks`/`venv`/`gh` 是否真的全缺；

**验证结论由子智能体独立给出，记录在其返回中；任何 FAIL 都按上一版的处理办法：改文档，不辩解。**

## 4.2 验证反噬到本版的一处自相矛盾（已修）
`steps/STEP-00E-*.md:84`（继承自 V0.10.0）写着「前端一半已满足（**本机实测**）：node_modules 存在、pnpm/Node 22 在 PATH、vitest 366 全过」。
这正是本版 D-V6-01 要消灭的那个词，却留在我自己发出的卡里——**如果我不自净，下一位执行者读到它就会在 Windows 上跑 `pnpm`**。
已改为 `采信[REMOTE]` 并就地注明：换到本机（`node_modules`/`pnpm`/`gitleaks`/`venv`/`gh` 全无）该半边即不成立，验收前须在目标机重跑。
教训记在这里而不是只改文件：**继承卡不是别人的产物，随件复制过来就是本版的断言**；下一版做继承时应逐行扫一遍"本机/实测/已满足"这类无主语断言。
