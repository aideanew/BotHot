## 0. 一句话结论

**V0.10.0 把主干判成「单红」（CI 连续 4 绿、Security 仍红），并把 UI 关键路径裁为"今天就开、本机依赖本就就绪"。这些结论在它自己那台 Linux 沙箱（`/workspace/work/BotHot`）上是成立的——但它把它们写成了"本机"。**
**在这台 win32 上我实测：`apps/web/node_modules` 不存在、`pnpm` 不在 PATH、`gitleaks`/`venv`/`gh` 全缺。执行者按 V0.10.0 §3.1 的字面去跑 `pnpm typecheck`，得到的是 command-not-found，不是通过也不是失败。**
**所以 V0.11.0 不增功能卡，只做两件事：①把"哪台机器"变成卡面必填项（机器 × 入口矩阵 + 每条验收命令标注 [本机]/[依赖机]/[CI]，并给"机器不可用时的分支"）；②把已经拖了五个版本的 `decision-log.md` 登记做完——登记是机械动作、签字栏留空、不代任何人签。**
**同时校正一处跨版本口径：V0.10.0 的 row 4 已立对原则（"另一台机器的读数不跨机继承"），但 §3 与卡片正文仍写"本机"，自相矛盾；本版按该原则把全部环境断言拆成 [本机]/[REMOTE] 两栏。**

## 0-b. 第二增量结论（基线 `17c5d28`，2026-10-15 12:04 签）

**五个版本连续停在"规划—复审"循环里，卡的不是任务不清，是两个从未固定的前提：①没有裁决台账（无人签字，谁都不敢按 A 方案开工）；②验收环境/机器身份含糊（同一个"本机"在两台机器上取值相反）。**
**这两件事在本轮同时被解掉：10 项 BLOCKING 已按用户授权全部签入 `docs/03_solution/decisions/decision-log.md`（§1 生效 2026-10-15 12:04，签字列明写"用户授权代选"，不冒充人手签）；机器身份由 D-V6-01/02 + D-V4-01 定死——正式验收面 = CI `ubuntu-latest`，Win10 升为一等开发平台并新增 CI `windows-latest` 门，本地读数一律标 `@win` 且只算冒烟。**
**因此第一增量那句"不增功能卡"在本段作废：新增 STEP-00X（9 任务 / 1.5 人日）就是把"Win10 能装、能跑、能验"本身立成可验收的交付物。**
**仍未解的一件事，且只有用户能给：外部凭据（付费文章源 API key、生产库账号、真渠道密钥）。缺它们的工作按 D-V2-06 停在"生产实跑"之前，不猜、不伪造。**
