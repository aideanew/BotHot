## 1. 复述
BotHot 是「公众号内容 → 发现/清单/入库 → 热点聚簇评分与日报 → RAG 问答 → 多渠道推送 + 站内通知」的内容机器人平台；身份锚 `users.sub`、余额等级永不落库、队列在 PG（SKIP LOCKED）、前端 Next.js 15 经同源 rewrites 打后端。本轮用户要的是：**检查未被实现的需求、建立统一规划体系**，并要求核心/高难（尤其 UI）由规划方亲自完成、中简单卡发布给其他 Agent。

## 3. 三对矛盾（辩证统一）

### 矛盾一：「规划方亲自完成 UI」↔「本机无法验证 UI」
- 正题：用户连续三轮明确"核心+高难尤其 UI 你自己完成"，V0.10.0 已据此裁 D-V5-01 开跑。
- 反题：这台机器 `node_modules`/`pnpm` 皆无（F-04），写出的 TSX 无 typecheck、无 vitest、无 dev server ⇒ 直接违反 Done 定义"自动测试可复现"，也违反指令 §9.3"禁止自证通过"。
- **统一**：把"谁做"与"在哪做"解耦——执行者仍是规划方（不转派给别人），但**执行点必须是一台依赖可就绪的机器**，并把这点写成卡面必填的 `@机器` 标签（D-V6-01）。障碍从"授权问题"降格为"一次 `pnpm install`"，可被单一动作清除；我不再用"没授权"当挡箭牌，也不用"没环境"偷偷改写成"已完成"。

### 矛盾二：「五个版本各建一套大纲」↔「统一规划体系」
- 反题很硬：V0.7/V0.8/V0.10 一天内三度重排，V0.11 若再排一次就是第六套，与"统一"相反。
- **统一**：本版**不重排、不改任务数、不新增功能卡**（F-10 证明 V0.10.0 计数自洽），只补一层所有人都缺的公共件——机器归属性 + 台账落地。大纲的"统一"由 `steps/` 全量随件 + 编号不复用来保证，而不是由"每版重写"来保证。

### 矛盾三：「采信另一台机器的读数」↔「不跨机继承」
- V0.10.0 自己立了原则（row 4），却又在 §3 写"本机就绪"。
- **统一**：原则保留、执行到位——`采信[REMOTE]` 是一等公民标签（F-06/F-07 就这么记）：既不否定（那是别人的真读数），也不升格为本机事实（我测不到）。RV 的"CI 半边"因此从"已满足"回退为"待复核 run id"，这是一次**必要的降格**，不是抹除。

## 4. 两条根因链

### 4.1 「decision-log 缺席五版」链
```
V0.6.0 立"登记 + 24h 无人否决即生效"机制
 → V0.7/0.8/0.9/0.10 每版都写"建 decision-log.md"
   → 每版都把它当成"需要人来"的动作（怕规划方自证通过）⇒ 整卡停摆
   → 连锁：D-V3-01 未生效 ⇒ 01/02/04 不开工；D-V3-03 ⇒ 13 不开工；D-V3-06 ⇒ 14 不开工
 → 根因是机制被写成一个动作，而不是缺人
 → 本版：把"登记（填默认值、签字栏留空、生效时间起算）"与"签署（人勾 BLOCKING）"物理分离，
   并当场执行前者 ⇒ 计时开始，五版停摆的唯一免死金牌消失
```
### 4.2 「环境断言不落地就复用」链
```
V0.7.0 F-10: 本机 node_modules 不存在 → 判 UI 阻塞
V0.10.0 row 4: 沙箱里 node_modules 存在 → 判"UI 可以今天开"
  → 两条都对，但都写成"本机" ⇒ 下一位执行者按字面跑，拿到 command-not-found
    → 现象层：读数冲突；本质层：读数没有携带"采集机"这一必要维度
      → 与 V0.9.0 的 S-06.1（时点错标）同族：一次缺"时间戳"，一次缺"机器戳"
      ⇒ 治法同构：让读数字段强制带来源（本版 D-V6-01/D-V6-02）
```
