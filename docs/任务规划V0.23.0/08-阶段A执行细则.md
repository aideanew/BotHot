## 1. 架构前提：契约链是三段，八态契约缺的是"机器可校验的那一段"

```
唯一源            apps/api/app/contracts/<域>.py          （Pydantic，extra="forbid"）
   │  gen_contracts.py（--check 在 CI 跑，ci.yml:138-139）
   ▼
schema 产物       packages/contracts/schemas/<域>.schema.json
   │  gen_contracts.py 的 CONTRACT_TS_DOMAINS（:298-301）
   ▼
TS 产物           packages/contracts/src/<域>/dto.ts      （emitDeclarationOnly，纯类型）
```

八态契约今天的状态是**半挂在链外**：

| 半 | 内容 | 现在在哪 | 归谁 |
|---|---|---|---|
| 机器可校验的半 | `State` 八值枚举、`StateRendering` 五字段形状 | 只在冻结稿 `docs/任务规划V0.12.0/contracts/ux_states.schema.json` | **STEP-64 搬进链** |
| 叙述的半 | `x-core-views` 六视图 × 每视图 states 文案要求 | 同上 | 留在冻结稿当设计说明，**不搬** |

**为什么不搬叙述**：叙述是中文散文，Pydantic 生成不出来；硬搬只能手写一份新的中文散文，
那就是"一份形状两个真源"的老病。叙述的**可执行化**方式不是搬进 schema，而是
变成 STEP-65 的 vitest 断言——**把散文变成可跑的判据，比把它抄进 JSON 更硬。**

### 2.2 方案 A（默认）：`ux` 作生成域

**新增 `apps/api/app/contracts/ux.py`**（形制照 `app/contracts/engine.py`）：

```python
from enum import Enum
from pydantic import BaseModel, ConfigDict

class State(str, Enum):
    """八态枚举。顺序与冻结稿 definitions.State.enum 逐值相同——
    顺序也判，因为 e2e 会按枚举顺序生成用例标题，顺序变了报告就对不上。"""
    initial = "initial"
    loading = "loading"
    empty = "empty"
    success = "success"
    error = "error"
    forbidden = "forbidden"
    unauthenticated = "unauthenticated"
    degraded = "degraded"

class StateRendering(BaseModel):
    model_config = ConfigDict(extra="forbid")
    state: State
    surface: str
    text: str | None = None
    actionable: bool
    retryAllowed: bool
```

> 注意：`retryAllowed` 用驼峰，因为冻结稿的 `StateRendering.required` 写的就是驼峰
> （`["state", "surface", "actionable"]`，属性名 `retryAllowed`）。**照抄冻结稿的键名，不改成 snake_case**——
> 改了就不"逐值相等"，判据会红，而红的原因会是"我们改得好"这种最坏的假红。

**改 `scripts/gen_contracts.py` 两行**：

```python

"ux": "app.contracts.ux",

# CONTRACT_TS_DOMAINS（:298-301）
"ux": "ux",
```

**改 `apps/api/tests/test_contract_jsonschema.py`**：
- `DOMAINS` 加 `"ux": ("ux_states.schema.json", ux_contract.CONTRACT_DIVERGENCES)`
- 顶部加 `from app.contracts import ux as ux_contract`
- 新增一条断言（**唯一新增判据**，不新增文件、不新增 CI 步骤）：

```python
def test_ux_state_enum_matches_frozen_draft() -> None:
    """八态枚举的唯一源已迁到 app/contracts/ux.py；本断言钉住它与冻结稿逐值同序。
    这条断言是 P-80「归位」的机械凭据：搬完之后，冻结稿从"唯一源"降级为"被核对方"。"""
    draft = _load(DRAFT_DIR / "ux_states.schema.json")
    product = _load(SCHEMA_DIR / "ux.schema.json")
    assert product["$defs"]["State"]["enum"] == draft["definitions"]["State"]["enum"]
```

### 3.3 聊天降级的实现形态（不改协议）

`useSseAsk` 的 `runQuestion` 现在只有一个 catch（`:93-102`）。改法：

```ts
// 终态分类：只加一层 kind，不动既有文案映射
const DEGRADED_CODES = new Set([30002, 50002]);
...
catch (err) {
  if (ctrl.signal.aborted) return;
  if (err instanceof ApiError && isAuthError(err.code)) { onUnauthorized(); return; }
  const degraded = err instanceof ApiError && DEGRADED_CODES.has(err.code);
  const text = degraded
    ? "引擎暂不可用，请稍后重试或换个空间"
    : err instanceof ApiError ? err.message : "回答生成失败，请稍后重试";
  patch(answerId, { content: "", streaming: false, error: { text, question, kind: degraded ? "unavailable" : "failed" } });
}
```

慢响应：在 `ask()` 里起一个 `setTimeout(15_000)`，若此时仍无首个 delta 且未 abort ⇒
`patch(answerId, { slow: true })`，由 `ChatMessageList` 渲染「响应较慢，仍在生成…」；
收到首个 delta 或终态时 `clearTimeout`。**提示不中断流**（契约原字是"给「响应较慢」而非静默"，
不是"超时就断"）。

`ChatMessage` 类型（`components/chat/types.ts`）加两个可选字段 `kind?: "unavailable" | "failed"`、
`slow?: boolean`——**这是本卡唯一允许改的类型文件**，且只加可选字段，不改既有字段。

### 3.4 为什么这四个用例要放 `apps/web/tests/` 而不是 e2e

- e2e 走 build 产物 + 真浏览器，一次跑几十秒；这四条判的是**渲染分支**，jsdom 就够；
- 本机无 Playwright 浏览器二进制（P-83 的读数），e2e 在本机跑不了，放 e2e 等于这四条永远只能 @ci 取；
- 与既有 `ask-sse.spec.ts` / `r061-sse-ask.spec.ts` 同族，工具链一致。

## 4. STEP-66 细则

### 4.1 identity：只内省，不改列

`DOMAIN_ENTITIES` 加 `"identity": ("entities", ["User"])`。
`User` 在 `apps/api/app/models/entities.py`（与 `KnowledgeSpace` 同模块），机制与 `knowledge` 域完全一致。
**禁止**为了"让产物好看"去改 `User` 的列名或加 `__contract__` 之类的东西——
那会把"库形状"变成"为契约而生的形状"，是本仓最忌讳的反向驱动。

### 4.2 撞名守卫会响，这是好事

`gen_contracts.py:258-262` 对"同名不同体"直接 `SystemExit`。若 `User` 与既有 `$defs` 撞名：
**改名，不改守卫、不改既有 def**。守卫响一次，说明契约里真的有两个不同的东西叫一个名字，
这正是它存在的理由。

### 4.3 chat 的两个类型归 `shapes`

`ChatCitation` / `ChatAnswer` 移进 `app/contracts/shapes.py`。
`shapes.py` 是"线上 `data` 形状"域（STEP-47 定的），这两个类型正是线上形状，归属正确。
`types.ts` 改成 `export type ChatAnswer = Shapes.ChatAnswer;` 这种别名，字段清单不再手写。

### 4.4 `MeData` 改别名的正确姿势

```ts
// 改前（types.ts:19-32）：14 行手写字段
// 改后：
export type MeData = Shapes.MeView;   // 若 shapes 里已有 MeView
// 或（若无 MeView 而有等价 def）：新增 def 后生成
```
**判据是 `grep -c "is_admin: boolean" types.ts` = 0**，不是"看起来像别名"。
若 tsc 报 `MeData` 缺字段 ⇒ 手写类型与后端本就不一致，按 `get_me` 三条分支字典为准改前端。
