# 02 需求拆解与辩证分析（main@53ebc4a）

## 1. 复述：项目要解决的核心问题
BotHot 把公众号内容做成一条可运营链路：**发现（多上游渠道）→ 清单 → 入库（去重/标准化/评分）→ 热点聚簇与日报 → RAG 问答 → 多渠道推送 + 站内通知**，身份全部挂在主平台 SSO（锚点 `users.sub`，余额与等级永不落库），作业队列走 PostgreSQL 的 `FOR UPDATE SKIP LOCKED`，前端 Next.js 15 经同源 rewrites 打后端。用户此刻要的是：**看清哪些需求还没实现、历史改动与异常在哪，并产出一套能交给 N 个互不通信的执行者并行开工的规划**。

## 3. 辩证统一的四对矛盾（本版的主张是把它们当同一件事的两面）

### 矛盾一：深度（复审 rigor）↔ 宽度（需求覆盖）
V0.6.0/V0.7.0 在采集域挖到 P-4/P-3 的真缺陷（深度有效），代价是 12 条需求只覆盖 2 条（宽度失效）。
**统一**：宽度已经补齐（V0.7.0 的 13–19 + 覆盖矩阵），本版不再在宽度上加码，而是解决第三维——**可执行性**：卡再全，没有签字与验收环境就等于零。

### 矛盾二：证据（证明脚本）↔ 事实（真实套件）
10,406 行证据脚本对 0 行业务改动；而那条回归恰恰是真实套件红、证明台全绿（V0.7.0 F-72）。
**统一**：不废证明台（它能抓变异级缺陷，第十九轮仍在发现真问题），而是让两者**耦合**——净增脚本必须净增 pytest 用例（04 §5 的耦合门）。这是把"对立"转成"互为条件"。

### 矛盾三：速度（并行派工）↔ 一致性（共享工作树）
并行 N 个执行者的前提是契约与所有权；现实是同一工作树里多个会话互相改文件、互删环境（V0.8.0 的 PG 实例、本版消失的 `node_modules`）。
**统一**：本版把"环境"和"敏感形门"从背景升格为交付物（00E/00P），并行才成立。

### 矛盾四：自律（规划方不越权）↔ 授权（用户已说"全部实现卡含 UI"）
我上轮把只读与实现的冲突上交，用户裁定"授权全部实现卡，含 UI"。本轮我照裁定推进了吗？——**部分**：R0/16 的代码已落（上轮），UI 仍不能做，因为阻塞换了：不是授权，是 `node_modules` 不在（F-10）。
**统一**：授权的表述不变，卡的前置条件更新（14b/15 的阻塞从 D-V3-00 改为 00E）。

## 4. 三条根因链（穿透到前提层）

### 4.1 「三版 0 签」链——为什么治理永远差一步
```
V0.6.0 立默认裁决机制（登记 + 24h 无人否决生效）
  → V0.7.0/V0.8.0/V0.9.0 三轮 decision-log.md 均不存在（F-11）
    → 根因不是"人没空签"，而是卡的 S0G.1.1 把「登记」和「签字」写成同一个动作
       登记需要人来（怕规划方自证通过）→ 整卡停摆 → 签字更无从谈起
  → 连锁：D-V3-01 未生效 ⇒ 01/02/04 不能开工；D-V3-03 未生效 ⇒ 13 不能开工；D-V3-06 未生效 ⇒ 14 不能开工
  ⇒ 本版：S0G.1.1 拆成"登记（执行者可做，签字栏留空）"＋"签署（仅 4 个 BLOCKING）"
```

### 4.2 「已实现、未验收」链——R0/16 为什么卡在第二步
```
V0.7.0 07 §7.3 与本版 01 F-15：真库读数本机取不到
  → V0.8.0 §4 把它标成 BLOCKING（本机 PG 实例 /tmp/pgd 被并发会话清除）
  → 本版复现同一形态：node_modules 从"存在"变"不存在"（F-10）
    ⇒ 环境是共享工作树的公共品，会随别人动作变化，不能引用上一版的工具链状态
  → 后果：R0/16 的代码在 HEAD 完好（F-03），但没有一条 `0 failed` 读数 ⇒ 按 04 §4.14 不算 Done
  ⇒ 本版：STEP-00E 单独立卡，"make verify-backend 一条命令出读数"就是它的 Done
```

### 4.3 敏感形自伤链（本版新增认知）
```
规划文档要解释"为什么排除某文件" → 顺手抄了占位 DSN 字面量（V0.7.0/06）
  → 又为了让人能复跑判据，把扫描正则也抄进文档（同一篇）
    → gitleaks 扫相邻形，不看意图 ⇒ "反凭据文档"自己成了新增命中（f70d52f）
      → 工作树打码只防未来；历史指纹仍在，必须 .gitleaksignore 逐条登记（00S，需真二进制）
  ⇒ 本版：00P 把扫描做成 evidence-check 阻断步 + 立规"文档不内联敏感形与正则"
```
