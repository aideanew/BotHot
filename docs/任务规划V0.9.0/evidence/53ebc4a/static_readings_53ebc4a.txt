### S-06.1 时点归属更正（本版自己踩的坑，独立验证者抓出）
本文件初稿把 10,406 / 9,194 标在 `2315cda` 名下，**那是错的**：这两个数是**当前 HEAD `53ebc4a` 的提交态**，
而 `2315cda` 的提交态是 **9,934 / 8,722**。原因是我在会话中段采集，采完后 main 又前进了一个提交（第十九轮），
我直接把工作树现值挂在了旧哈希上——正是我上一版批评别人的"把转抄/过期读数写成本时点值"。
复算口径（提交态用 `git cat-file`，不看工作树）：
```
2315cda 提交态：py 文件 11 个，全量 9,934，EVD-V2-00R+02 口径 8,722
53ebc4a 提交态：py 文件 11 个，全量 10,406，EVD-V2-00R+02 口径 9,194   ← 本版引用值
工作树现值：10,406（与 53ebc4a 提交态一致）
```
⇒ 结论：**"每轮的基线哈希必须与该轮所有读数的采集时刻绑定"**，且凡引用行数类指标，须同时给"提交态"与"工作树态"两个口径，
否则共享工作树里的漂移会被误读成上一版的读数错了（本次 V0.8.0 的 9,519 与本版的 10,406 之间并无矛盾，只是不同采集时刻）。
