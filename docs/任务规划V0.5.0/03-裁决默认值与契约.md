## 2. ADR-0011 规范文章键（D-V2-01 默认值 A 的规格）

```
canonical_article_key(url: str) -> str
  p = parse_wechat_url(url)                       # article_identity.py:54，唯一解析源
  if p.host == "mp.weixin.qq.com":
      if p.biz and p.mid:   return f"b:{p.biz}:{p.mid}:{p.idx or '1'}"
      if p.short_token:     return f"s:{p.short_token}"
  return "h:" + sha256(normalize_url(url)).hexdigest()[:32]
normalize_url：小写 scheme/host；去 fragment；去追踪参数（chksm、scene、srcid、from、isappinstalled、clicktime、enterid、sessionid、ascene、devicetype、version、pass_ticket、wx_header、nettype、lang、exportkey、key、uin、utm_*）；其余参数按键排序。
```

- 契约正则（contracts/collection.schema.json `ArticleKey`）：`^b:[A-Za-z0-9+/=_-]{8,64}:[0-9]{1,12}:[0-9]{1,2}$` | `^s:[A-Za-z0-9_-]{8,64}$` | `^h:[0-9a-f]{32}$`。
- 不变量（契约测试锚）：任何输入的键 ≠ `"s"`、长度 ≥ 8；同一篇文章的长链（含/不含追踪参数）→ 同一个 `b:` 键；同号两篇不同 `mid` → 不同键。
- 短链与长链：首次抓取前短链只能得 `s:` 键；抓取后经 `ShortLinkMap(short_key → article_key=b:…)` 归一（kb.py:274-278 改写入规范键）。
- 历史兼容：缓存未命中规范键时，**仅短链**再用旧裸 token 查一次（只读，不改写；改写由 STEP-07 回填）。

## 3. 清单↔资产对齐契约（D-V2-02 默认值）

| 对象 | 字段 | 语义 |
|---|---|---|
| `article_manifests.external_id` | 不变 | 渠道上游 id（或无 id 时 = 规范键），渠道内去重 |
| `article_manifests.article_key` | **新增** VARCHAR(128) NOT NULL DEFAULT '' | `canonical_article_key(url)`；与 `content_assets.external_id` 同一键空间 |
| `article_manifests.status` | 扩为四态 | `DISCOVERED → ENQUEUED → INGESTED`；`ENQUEUED → FAILED`；`ENQUEUED`（stale 超时）→ `DISCOVERED` |
| `job_items.manifest_id` | **新增** VARCHAR(36) NULL FK ON DELETE SET NULL | 入列时写入；worker 终态时回写清单状态 |
| Diff | `_compute_new_manifests` | `status='DISCOVERED' AND article_key NOT IN (READY 资产 external_id) AND id NOT IN (活动 Job 的 manifest_id)` |

迁移串行：`ab1005w5b → ab1006c1a（STEP-04）→ ab1006c2a（STEP-08）→ ab1006c3a（STEP-09，条件）`；任一时刻只有一个 STEP 持有下一个迁移号；改模型的提交必须同提交重新生成 `packages/contracts/src/subscription/dto.ts`（否则 `gen_contracts --check` 红）。

## 4. 渠道行契约 `WorkListRow`（STEP-03）

| 字段 | 必填 | 规则 |
|---|---|---|
| `id` | 是 | 上游稳定 id；上游无稳定 id ⇒ `canonical_article_key(url)`，并置 `id_fallback=True` |
| `url` | 是 | 原文链接；空 url 行在 provider 内丢弃并计数 `rows_dropped{reason=no_url}` |
| `title` | 是 | 可为空串 |
| `publishTime` | 否 | ISO 8601 / epoch 秒 / epoch 毫秒 / RFC 822 四种均须被 `_parse_time` 解析 |
| `digest` | 否 | — |
| `id_fallback` | 否 | 供 STEP-05 指标区分 |

- 所有 `query_work_list` 实现必须返回 `WorkListRow`；`_map_row` 优先读 `id`，`_ID_KEYS` 保留旧别名作兼容；缺 `id` 时防御兜底 = 规范键并计数，**不再静默 return None**。
- 契约测试：`tests/test_provider_contract.py` 对 `fixtures/provider_payloads/` 全部样本参数化，新增渠道只需加样本即自动纳入。
