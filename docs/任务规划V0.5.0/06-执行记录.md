## 5. 本会话踩到并留档的环境事实

1. `git ls-tree -r --name-only <c> -- <path>` 的 pathspec **相对当前目录**：在 `EVD-V2-02/` 里跑恒返回空。
   我一度把「命令没给读数」读成「目录不存在」的读数，错判已订正（`EVD-V2-02/README.md` §4.11 头部、§4.12 id 35）。
2. 控制台码页 cp936：任何中文读数必须先落 UTF-8 文件再读，直接打印会 `UnicodeEncodeError` 或成乱码。
3. win32 `Path.write_text` 把换行写成 `\r\n`；`core.autocrlf=true` 且 `.gitattributes` 只钉 `*.sh eol=lf`，
   所以纯换行改动下 `git diff --stat` 是**空的**——比对一律走 `read_bytes`/`hash-object`。
4. `python -O` 会剥掉裸 `assert`：凡「取不到就该停」的地方必须是打印 + `SystemExit`，不能是 assert。
5. 把敏感形**抄进解释为什么要防它的正文**，会自己给门禁新增检出项——所以扫描必须跑在待提交的
   `git diff --cached` 上，只跑工作树目录会漏掉改文档那一步。
6. 本机内存吃紧（`GlobalMemoryStatusEx` 实测 load 98% / avail 0.15 GB）时，反证电池会**成串**报
   `INCONCLUSIVE` 并最终 `MemoryError`，同时 bash 侧出现 `spawn UNKNOWN` / `0xC0000142`。这三件事同时出现
   是资源问题，不是判据问题——按本项目纪律 `INCONCLUSIVE` 本来就不算红，所以处置是**先释放资源再复跑**
   （本轮：清掉崩溃运行遗留在系统临时目录的 `n_r9_*` 副本、改串行执行），而不是去改判据或把期望档位放宽。
   顺带一条：`cmd && x || y` 里包一层 `; echo rc=$?` 会让后台任务通知报来**包装命令**的退出码，
   被包的那条崩了通知仍写 exit 0——后台跑的判据一律以它自己写进文件的末行为准。
   勘误（第十四轮 D 组 D-14-03）：这一行当年观测到的 NTSTATUS 是 `0xC0000142`（`STATUS_DLL_INIT_FAILED`，
   与 `spawn UNKNOWN` 同现），在 `a576bc2` 被就地误写成 `0x00000142`——那不是任何一个错误码，
   而 `grep -rln "0xC0000142" docs apps` 当时已为零命中，等于把观测值抹掉。现按 `a576bc2^` 的原文回滚，
   历史结论本身不动。教训记在这里而不是只记在代码里：**要躲归一化正则，改的是口径而不是读数**，
   而这一条根本不在留档里（驱动的 `MEMADDR` 归一化只作用于 `out_s213.txt`），没有任何理由动它。
7. `shutil.copytree(..., ignore=ignore_patterns("__pycache__"))`（电池 `stage()` 那行）意味着
   **副本世界里根本没有 `.pyc`**：任何「往 `__pycache__` 里放什么」型的变异在电池里测不出效果
   （判据照样绿，期望 RED 却拿 GREEN）。第十三轮补孤儿编译件判据时就撞在这上面——落点是让那一发
   直接改**判定函数的返回值**（把结果写成非空），而不是去改目录扫描的分支。
8. Python 的链式调用在 AST 里是 `Call ← Attribute ← Call`：`select(X).where(...)` 中 `select(...)`
   的父节点是那个 `Attribute`，不是 `.where(...)` 的 `Call`。沿父链爬方法时少爬这一跳，
   「链上有没有 `.limit(1)`」会恒读成空链——第十三轮实测：修好之前 **AF-S2 在未变异的 kb.py 上就报红**
   （基线红 ⇒ 整批判据不可用，靠的正是电池 N-00 那一档把它拦下来）。
9. 「判末行」这类收紧要先把**驱动自己加的尾巴**剔干净：段末那条 `rc=N`、以及 rc=2 时补的
   INCONCLUSIVE 标注都不是 harness 的裁决行。漏剔就会在每一次正常交付上假红（本轮自查抓到，
   并为此在 M 段各配一档「带尾巴必须静默 / 只剩尾巴必须点名」）。
10. 自指措辞是**模板字面量**的一种：留档每轮由驱动整份重打，那句「跑到这一轮时撞到过 …」每重印一次
    就把所指换到当前这一轮，第八轮那次 `OSError [Errno 22]` 因此在下一轮的纸上仍然自称刚发生。
    只改措辞管不到下一轮，所以这一条的落点是**扫描**（驱动源码 + 拼好的整份留档，落盘前后各一遍）。
    配套的坑：扫描器要扫自己的源码，登记表就**不能写成字面量**——`("本" + "轮", …)` 这种拼接不是
    打字游戏，写成字面量的那一行会永久命中自己。
11. `git log -S"<文本>"` 报的是「该文本出现次数**发生变化**」的提交，也就是引入与删除**两端**，
    不是「引入那一笔」；把它读成「唯一命中 = 引入」会漏掉自己刚做的那次删除（第十四轮 D 组 D-14-07）。
    同一条命令的第二只脚：git 的 pathspec **相对当前目录**解析，在证据包目录里用仓库根长路径会
    **静默给空结果**——那是「命令没给读数」而不是「没有命中」（这条 §4.11 已经记过一次，本轮复踩第二次，
    说明只写在不显眼的地方等于没写）。
12. 「判据只看真包」的探测档在反证电池里**没有读数**：电池 `stage()` 时 ignore 了 `__pycache__`，
    副本世界里根本没有 `.pyc`，于是「见谁都咬」那种写法在旧口径下测不出（第 7 条记的就是这个妥协）。
    第十四轮把孤儿编译件判据改成**自己造一棵三种位置都有的小树**之后，同一发变异第一次有了红档——
    教训一般化：判据想让反证打得中，就得把被测世界自己造出来，而不是依赖仓库当时的样子。
13. 「存在」不等于「承重」：`ast.walk(node)` 找一个 `return None` 会被**嵌在下一层条件里**的那份满足，
    而那一层的条件可能根本不成立（第十四轮 C 组 C-14-02 的 `if fragment.isalpha(): return None`）；
    同理 `tree.body` 那一层的用例清单会漏掉 `Test*` 类里与 `if True:` 里被 pytest 真收集的函数。
    收紧成「分支体的**直接**语句」/「收集口径」之后，两端各要一发「嵌一层」的变异当反证，
    否则同一族下一轮还会再来。
14. **对账「探测范围」时，应扫集合不能从被扫的那份清单现取**（第十五轮 E 组 E-15-05 的现场）：
    自指扫描把扫描面从「驱动 + 全部在册件」缩成「只扫驱动」，旧判据只问「读到的文本里有没有措辞」，
    而兄弟台此刻是干净的 ⇒ 那一发变异跑出 `rc=0`，反证打不中。补的那条判据读的是
    「应扫集合（从在册登记表 `EV_PY` 现取）」与「实扫集合」，与内容无关，缩面当场红；
    若写成「应扫集合从 `face` 现取」就是自证循环——缩面时两边一起变小，那条判据永远绿。
    同一族的另一格：电池里那一发标注成 GREEN「等价」会把削弱洗白成同权写法，
    正确的记法是**登记为残余**（单发替换打不中的组合变异，写下来而不是假装测过）。
15. **共享工作树里「门禁读磁盘」会把别人的在飞件读成我的缺陷**（第十五轮重放时的现场）：
    另两个会话当时未提交的改动包括 `apps/api/app/services/kb.py`（STEP-R0 的第三条锚）、
    `apps/api/tests/test_kb_multisource_anchor.py`（两条 R0 用例）与新建未跟踪的
    `apps/api/tests/test_alerting_default.py`（STEP-16）。同一份 AF 台两档读数：
    脏工作树 `FAIL 基准（未变异）就有红判据：['AF-B6', 'AF-S7']`、`da4095a` 干净视图 `SELF-TEST PASS`。
    处置是**换视图而不是改判据**：`git worktree add --detach /tmp/r15clean da4095a` + 只叠本批五份文件
    （叠完 `git status --short` 必须恰好那五行——用 `git diff --name-only` 当清单会把别人的件搬进来），
    在干净树上跑三道门与整份重放，`out_s213.txt` 按字节拷回并 `sha256sum` 两遍对账。
    判据若改成「刚好通过别人未提交的代码」，等于拿别人的在飞状态给自己背书；
    而 R0 那条锚与本步契约的冲突是真问题，另立 J-8 交对端拍板，不在这里自行让步。
16. **读数要与被比的对象同单位**（第十六轮自查，落在门禁自己身上）：`EVD-V2-00/g24_static_check.py`
    的 E501 从前按**字符数**判，而 ruff 的 120 是**列宽**（East Asian Width `W`/`F` 占 2 列）。
    锚点是实测对上的那一行：`apps/api/tests/test_env_isolation.py:68` 112 个字符 / 134 列，
    ruff 在 `65f508b` 报的正是 134。于是「现读该行 112 列 ≤120」这句**看起来像读数的错话**
    被写进过 STEP-00C 卡并据此把一条未做的任务标成 ✅——同一批还查出四条**来源标错**
    （把有依赖环境采集的入库件写成「本地」读数：`ruff/mypy`、`gitleaks`、`ci.yml` 五步、CI run 结论），
    五格一并降级并各配现读命令。教训一般化：①比对之前先问「这两个数是同一个单位吗」；
    ②凡是「本地/CI/他机」来源之差，写下来时必须带采集环境与文件路径，否则不可证的东西会被读成可证的；
    ③近似表比 CI 更严还是更宽要**逐条规则**说，不能一句「本表只降提交风险」盖过去。
17. **复现命令本身也是会被证伪的陈述**（第十六轮复核 C4b/C5 抓到两处，都是我的）：
    ① `git diff <提交> -- <路径>` 比的是**工作树**，不是「那一批」——同一份路径集合，双端写法
    `git diff --stat 78e3378 078dc30 -- …` 给 `37 ++ / 20 --`，单端写法在今天给 `75 ++ / 25 --`，
    多出来那一节正是别人未提交的第三条锚。取证类声明一律写双端或 `git show --stat <提交> -- <路径>`。
    ② §4.17 那条降级记录把落点写成「S2.1.4/S2.1.5 那一格」，而真正降级的是 **S2.3.2**；
    更糟的是我配的复现命令 `grep -n "S2.1.4"` 恰好能在文件里读到东西，于是「按命令跑过」这件事
    并不能发现命令指错了地方。**指错的复现命令比没有复现命令更糟**——它让下一个人在对的位置
    读出「没问题」。落点、格号、文件名这类可定位的东西，写下来时要跑一遍看它是否命中**那一条**。
18. **名单式判据永远差一个名字，而这族缺陷有两种修法**（第十六轮机制组 F-17-01…04 四格同因）：
    「认三种拼法」的扫描器漏 `.op(变量)`、`.contains(...)`、`text("… LIKE …")`；「列黑名单」的守卫判据漏
    legacy ORM `session.query(…).filter(…).first()`。① 能按**语义族**列的就按语义族列（会渲染成 LIKE 的
    谓词一族；`.op` 的模式串拼不出来就按可疑算——fail-closed 是显式选择而不是偷懒）；
    ② 列不出语义族的就翻成**白名单**（守卫体内除了量长度与留痕，任何 Call 都算第二条兜底），
    并把代价写成契约（将来要用没见过的函数必须先改口径，与 BD-12 的「宁严勿宽」同一处理）。
    同批还换掉一处**取样口径**：AF-B6 从手挑四档键长改成 16..45 逐档扫——手挑的问题不是挑得少，
    而是「样本集合在替判据说话」，`== 22 字符` 那一档恰好不在里面。
    另有两格本机**不关**，并写在判据名里而不是留给读者推：内容等值门（`if key == <魔数>`）要喂进那个
    魔数才在行为面出声、样本无法穷举；拼出来的名字（f-string、`"".join` 当字典键）要还原就得执行
    任意字符串，那是在门禁里开攻击面。明认盲区与残余的分工见 EVD-V2-02 §4.19 与 §7。
19. **别人的「在飞件」会变成「已入库契约」，那句话的读数要回去改**（第十六轮批次收尾时抓到的）：
    登记 J-8 时 STEP-R0 那条第三条锚还是未提交的工作区改动，本包据此把两档读数写成
    「脏工作树红 / 干净视图绿」；随后 `b2d0b66` 把它与 STEP-16 一起入库，于是同一台 AF 在
    **当前 main 的干净检出**上仍然报
    `FAIL 基准（未变异）就有红判据：['AF-B6', 'AF-S7']——self-test 结论不可用`。
    现读（自己复现，别信本行转述）：`git worktree add --detach /tmp/x 61358c3`，在
    `/tmp/x/docs/06_validation/evidence/EVD-V2-02` 跑
    `PYTHONIOENCODING=utf-8 python prove_anchor_fallback.py --self-test`，收尾
    `git worktree remove --force /tmp/x`。
    两条纪律由此得出：①**「在飞/未提交」是一种带时间点的状态**，写进台账必须带锚点，
    别人入库之后要回去把那句话改写成「两个已入库契约互相冲突」——否则下一轮读到的是过期解释；
    ②本包的留档只声明它证明的那一版磁盘状态（配方见 EVD-V2-02 §2b），**不**声明当前 main 全绿。
    「我的留档是绿的」被读成「main 是绿的」是这份证据包最容易被误读的地方，
    所以这句话现在写在 README §4.17 环境事实 1 末段与 §5 J-8 里，而不是等下一轮复审来告诉我。
