## 2. 六份契约（唯一源不变，本版只记增量）
唯一源：冻结 JSON Schema `docs/任务规划V0.12.0/contracts/*.json` → 后端 `apps/api/app/contracts/*.py` 镜像 → `python scripts/gen_contracts.py --check` 生成 `packages/contracts/src/**`（D-V8-05：jsonschema 校验）。禁止多源并存。

| # | 契约 | 本版增量 | 是否改冻结稿 |
|---|---|---|---|
| ① API | `POST /api/v1/bots/tasks` 请求体删除 `created_by`（响应保留，语义为创建者的 `users.id`）；`/admin/push channel=web` 的成功语义追加"已写站内历史"；10 个端点的最低秩是 operator | 否：冻结稿只覆盖 envelope 与采集域；推送域 DTO 在 `packages/contracts/src/bot/dto.ts`，由 STEP-01（收编 api 域）纳入 |
| ② Errors | 无新增码。operator 访问上述 10 个端点从 10004 变成业务码；`POST /bots/tasks` 不再出现 50001 | 否 |
| ③ Identity | `require_roles` 只能有一个参数（最低所需秩）；推送任务归属锚 = `users.id`；管理端越权面：user 访问 10 个端点必须是 10004（S25.1.2 矩阵固定） | 否：冻结稿 `x-rank` 与"取最高 rank"在单参数下与新约定等价 |
| ④ Resources | 无 | 否 |
| ⑤ Events | 无（站内通知历史复用 STEP-23 的预铸 id 规则） | 否 |
| ⑥ UX States | 推送页对 rank < operator 渲染 `forbidden` 态；建任务失败要渲染 `error` 态，不能沿用 mock 的成功态 | 否：使用冻结稿已有的状态枚举 |

### 契约自检
- [x] 前端只凭契约能写调用层：请求体删字段、响应不变、403 态有枚举可用。
- [x] 后端只凭契约能实现：归属来源、秩、历史写入三条都写进了卡面判据。
- [x] 数据端只凭契约能设计：不迁移、不改列。
- [x] 错误码覆盖已知失败路径：10004（秩不足）、30004（不存在）、10001（未登录）、50001 不再出现（作为回归判据）。
- [x] 管理端越权路径被禁止：user × 10 个端点 = 10004，由矩阵固定。
