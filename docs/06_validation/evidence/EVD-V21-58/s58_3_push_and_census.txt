== 3. 推送标签（临时凭据：同一条命令内创建→使用→删除→核实） ==
  cred_written exists=True requested_mode=0o600 measured_mode=0o666 mode_is_600=False bytes=122 token_len=93
  push_ref=v1.1.4 push_rc=0
  cred_exists_after_rm=NO
  cred_parent_siblings=0
  推送输出（脱敏）：* [new tag]  v1.1.4 -> v1.1.4
  `git remote -v` 两侧 URL 均为 https://github.com/aideanew/BotHot.git，无凭据残留
口径照旧写清：这台机器上 POSIX 权限位不成立（请求 0o600 回来是 0o666），真正兑现的是
「存在时间压到一条命令内 + 删除后核实不存在 + 只挂这一次用的 helper」，不是 mode。
命令侧另加 `GIT_TERMINAL_PROMPT=0 GCM_INTERACTIVE=never` 与 `-c credential.helper=`（先清空继承的
helper，再只挂 store --file=本次临时文件），避免 GCM 抢先咨询把推送挂住。

  s58_3_tags_revlist_before.txt（454 行）→ …_after.txt（462 行）
      删除行数 0、新增行数 8（v1.1.4 的祖先里此前无标签可达的那 8 个提交）
一次自曝（记下来而不是抹掉）：三个 before 文件当时由 `Path.write_text` 写出，行尾被 Windows 默认
换行翻译成 CRLF，而 after 用 shell 重定向是 LF ⇒ 直接 `diff` 报「1,10c1,12」这种整片不同，
看起来像标签被大改，其实是行尾噪声。处置：对三个 before 做 `tr -d '\r'` 归一——每个文件先算
「去 CR 后的内容 md5」、归一后再算整文件 md5，两侧相等（ls-remote 78f5ff6ae999e2d48d7ab6eb405b5d41 /
show-ref 197a40b9805987b0d78886e6f60fdcd6 / rev-list 0e639f43bf9785288625ea0ce9a3672d），
所以归一动的只是行尾，不是内容。归一后 diff 才只剩上面那些新增行。
判据没有变松——变的只是我把两种行尾混在同一个对账里；下次同类对账一律两侧同机制写出。
