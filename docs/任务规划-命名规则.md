# 任务规划文档命名规则

> 依据 D-V12-17（2026-10-19，用户签 A）。自 **V0.16.0** 起执行；V0.1.0～V0.15.0 保持原名不改，避免断开各版之间的引用。

## 1. 版本目录
- 放在 `docs/` 下，命名 `任务规划V<主>.<次>.<修>`，例如 `任务规划V0.16.0`。
- 不搬到 `docs/04_planning/`、`docs/05_execution/`。

## 2. 每版固定 8 个文件
| 文件名 | 写什么 |
|---|---|
| `00-README.md` | 本版一句话结论、基线提交、第一刀、阅读顺序 |
| `01-事实基线与进度.md` | 拉取读数、CI、测试读数、各卡进度 |
| `02-需求复核与辩证分析.md` | 每个待追认项（P-xx）的复算与终判 |
| `03-裁决与契约增量.md` | 本版新裁决（同步追加到 decision-log）与契约变化 |
| `04-剩余可执行大纲体系.md` | 全部 STEP、依赖、关键路径、人日 |
| `05-风险自检与局限.md` | 风险、待用户输入、自检、局限 |
| `06-入库与双端一致.md` | 入库面、敏感形与 gitleaks、推送后双端读数 |
| `07-执行过程记录.md` | 本版规划过程中踩的坑与更正 |

某版确实不需要某个文件时，保留文件并写一行“本版无”，不删、不改名。

## 3. 子目录
- `steps/`：任务卡。
- `evidence/<短提交号>/`：本版证据，按所依据的提交分目录。
- `contracts/`：契约冻结件（有才建）。
- 生成表格的脚本放版本根目录，如 `gen_table.py`。

## 4. 任务卡
- 新卡：`STEP-<编号>-<中文短标题>.md`，编号沿用全局序（数字或 `00X` 形），标题不超过 20 字，不含状态词（“已实现”“待验收”等写进卡内状态栏）。
- 继承卡增量：每版一个文件 `STEP-继承卡增量-V<主>.<次>.md`，例如 `STEP-继承卡增量-V0.16.md`。
