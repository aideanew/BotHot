### 6.6 独立验证抓出的四处，其中两处是真缺陷（提交前已修）

验证者这一轮报回六个面，逐条自己复现后处置如下——**报回不等于成立，也不等于成因对**：

| 报回 | 我的复现 | 处置 |
|---|---|---|

### 12.2 两处 NULL 陷阱：这次的"修过头"比原来的 bug 更坏

`x NOT IN (子查询)` 只要子查询能产出**一个 NULL**，整个谓词就是 UNKNOWN ⇒ 该行不被选中。
`JobItem.manifest_id` 是这一步刚引入的可空列（D-V9-04），所以按 id/键减在途的子查询必须显式
`IS NOT NULL`，否则 Diff 从"永远 1 条"变成"永远 0 条"——采集全线静默停摆，比 P-2 严重一个量级。
两条守卫各有一发拆掉守卫的反证，判据用**计数**而不是"在某一段里"：主查询与在途子查询渲染出的
守卫文本一模一样，分段找会把"数错段"当成通过。

第二条 NULL 陷阱是设计上的：`article_key IS NULL` 的存量行**故意不入列**。它不是静默的——
Diff 附带一条 `manifest.diff.null_key_backlog` 计数告警，且本卡连库用例断言"事件必须出现、行数 ≥ 1"。
后果写进 D-V9-05：**STEP-07 回填之前，这些篇停止入列**。这条用例因此同时是回填前后的门槛读数
（回填后 `rows` 应变 0）。

## 13. 第四轮独立验证：S4.1.2 被判 FAIL，以及本轮返工（2026-10-17 下午）

### 13.1 验证者抓到的是什么

独立验证者（预算封顶：≤30 次工具调用、只跑本文件那两条 pytest）对 §12 交付的行为层出了 **FAIL**，
六问里两问答 `部分确认`，并新报一条 P1。核心那条不是我原来登记的"边界代价"，是**判据本身失效**：

- 来源卡（V0.7.0 STEP-04）S4.1.2 写的是「同篇**短链/长链**两形态各一条清单 ⇒ 只入列一次」；
- `canonical_article_key` 对同一篇文章的短链走 `s:<token>` 分支、长链走 `b:<biz>:<mid>:<idx>` 分支
  （`app/services/article_identity.py:162-170`），两支键**永不相等**；
- 所以"按 `article_key` 减"这件事对短链↔长链这一对**根本减不到**：既不减在途（同篇第二形态下一轮照排），
  也不减 READY 资产（`content_assets.external_id` 锚的是长链键）⇒ **P-2 在短链形态上原样复发**；
- 而我写的那条连库用例 `test_two_url_forms_of_one_article_enqueue_once` 里有一行
  `second.article_key = first.article_key`——把要证的等式当成了前提。用例恒真，抓不到上面任何一条。

状态：**存在缺陷 → 需要返工**（判据失真 + 行为未达卡面验收），已返工，见 §13.3。

### 13.2 为什么会写出一条恒真用例（同一族错的第四次）

`_ALT_URL` 我按"另一种 URL 形态"理解成了"长链换个追踪参数"，于是测试数据、断言、实现三者
按同一个**错误假设**自洽。这与本目录 §11 记的那族"判据绑在我的实现上"是同一个错，只是换了载体：
上一批是关键词扫描、这批是测试数据代做实现该做的事。可推翻的判据是：**用例里凡是给实现"补齐"
前提的赋值，都必须有一行断言证明它不是前提而是结论**——`second.article_key = first.article_key`
这种赋值出现而没有任何一条断言问"真实算出来是不是这个值"，就是恒真的形状。
本轮补的正是这条：新用例先 `assert short_row.article_key == f"s:{_SHORT_TOKEN}"` 并
`assert short_row.article_key != long_row.article_key`（把"两支不相等"钉成前提），
再去证"并键之后只入列一次"。
