## 2. 本段做的两件事（判据与深度分析在 09 §7）

### 2.1 第一件事：main 是红的，而红是我上一批推的

开工第一次取 `@ci` 读数就撞上：`CI`（ubuntu，正式验收面）对 `065a7f8` 是 **failure**，
失败步 `Tests (pytest) + coverage + skip gate`。上一批 §6.4 把连库行为面写成"待 `@ci`"——
那句话本身没错，错在**推之前没有把"待 @ci"当成未完成**：一个声称"待验证"的提交仍然是提交。

处置过程、根因（S2.3.1 只收掉了复刻的**函数**，漏了同批的**常量**）与逐条判据见 09 §7.1–§7.3。
出口：`8a95739` 推上去，`CI` run 38891816054 = **success** ⇒ main 回绿。

### 2.2 第二件事：同一段代码里还藏着一条我没测的生产缺陷

独立验证在审第一件事时报回更重的一条：第三条锚把规范键空间与迁移前裸 token 空间
**并成一次无序 `IN(...).limit(1)`**，谁赢由查询计划决定；旧末段键非单射，所以旧键那一支
可以指向另一篇文章的源 ⇒ `hitCache=True` 而正文错。我先自己现读复核（验证者的**结论**可以真而
**成因**可以是错的），确认代码与它自己的 docstring 相反，然后改逐键有序 + 登记 **D-V9-02**，
并把 D-V9-01 漏登记的后果补成 **D-V9-03**。细节见 09 §7.4。

**本段没有把"兼容层的残余风险"说成已修**：顺序解决的是竞争，库里没有规范键那一行时
旧裸 token 照样可能命中另一篇文章——那要等 STEP-07 回填。

### 2.3 顺带撞出来的工具谎：一条判据红了好几批

`prove_anchor_fallback.py` 的假会话不支持 `.join`，第三条锚一进去就抛 AttributeError ⇒
**AF-B6 自 S2.2.4 起一直是红的**，而红被读成了"用例有问题"而不是"工具跑不到"。
用 `--kb=` 指向未改版本做 A/B 确认既有性之后，修的是工具（补 `join`/按表分派条件/缺的列），
并新增 AF-S8（静态有序）与 AF-B8（行为）。同一轮还发现两发变异**一直是取消状态**
（锚出现 2 次，`_mutate` 直接不计），以及新判据被"按名字包含判"击穿一次——
这些全部写在 09 §7.5，含击穿面清单。
