## 3. 为什么"裸 import 很快、pytest 很慢"——这一段推翻了上一版的解释

`@win` 第一版探针（不换事件循环策略）跑出 `import app.main OK in 1.67s`，看似"根本没有问题"；
而换到 pytest 的条件下（`PROBE_SELECTOR=1` 复刻 `tests/conftest.py:26` 的 `WindowsSelectorEventLoopPolicy`）
同一命令 15s 被看门狗打断。差别只有一个：**psycopg 拒绝在 Proactor 事件循环上连接，
于是根本不发起 TCP 连接**，探测"看起来成功"地走了不可判定分支。

⇒ 结论修正为：这个缺陷在 Windows 上**只在测试条件下暴露**，而生产（uvicorn 自己管理 loop）是否命中
取决于运行器的事件循环形态。这一点卡面没写、我上一轮也没想到；把它写在这里而不是修一句注释。
生产侧真正的风险面仍是"黑洞地址 + import 期探测"，而它现在有两级上界。
