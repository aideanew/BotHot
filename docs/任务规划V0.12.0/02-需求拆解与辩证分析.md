## 5. 5W1H（本版关键判断：U-20 根因）
- **What**：windows-dev 全量 pytest 每次 35 分钟被取消；@win 本机 test_auth/backchannel 两文件 40s 超时；收集 262s（@linux 1.23s）。
- **Why**：import 期同步连库探测，无连接超时；Linux 拒连即时 RST 掩盖了它。根本原因是"启动路径里做无界 I/O"，Windows 只是第一个把它暴露出来的环境。
- **Where/When**：`app/main.py:281` 模块级 → `_assert_schema_current` → `app/db.py:53`；在每次 `import app.main` 与每次在无运行 loop 的同步上下文调用 `create_app()` 时发生。
- **Who**：规划方执行 00W（跨 app/CI/测试三面，opus）；独立验证者判定。
- **How**：先取栈（faulthandler）证实 → 探测引擎加 `connect_timeout=3` 并总限时 → 拆工作流 → 逐用例超时 → windows-dev 转绿。
- **What if**：① 栈显示卡在别处（如 TestClient/anyio 线程）→ H1 部分成立，S00W.1.3 二分；② 加超时后仍慢（每次 create_app 2-4s × 数百次）→ 测试侧 `DATABASE_URL` 指向立即失败的地址或提供 `SCHEMA_GUARD=off` 测试开关（S00W.3.2 二选一，以耗时读数决定）；③ windows-latest 镜像变更导致新失败 → 属 00X 范围，不在本卡调判据。

## 6. 双向钢人论证（H1）
- **支持**：代码路径确定无超时（F-04）；@linux 黑洞复现挂死（F-05）；卡点恰在第一个 import create_app 的文件（F-06）；"裸 import 快 / 经 conftest 慢"由事件循环策略差异精确解释（X-3）；@win alembic 无 PG 挂 150s 是同一缺陷的另一入口（EVD-V5-00X §5.2）。
- **反对**：① @win 单次拒连 2.05s，若每次 create_app 只多 4s，test_auth ~25 个用例不至于 40s 内一个都不过——**仍成立**：可能 psycopg 在 Selector+Windows 下对拒连的等待远长于 2s，需栈证实；② `-p no:asyncio` 仍卡——与 H1 不矛盾（探测走 asyncio.run，不依赖插件）；③ 也可能 TestClient 的 anyio 线程门户在 Windows 有独立问题——未排除，S00W.1.1 的栈会区分。
- **结论**：H1 = **部分确认**；足以支持"先加超时"这一低风险修复（无论 H1 是否为唯一原因，启动无界 I/O 都是 M-9 违反），不足以宣布 windows-dev 会转绿——那要 @ci 读数。
