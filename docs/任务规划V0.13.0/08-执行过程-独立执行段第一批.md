## 4. 辩证记录：本轮自己推翻过的判断

1. **最初把 `_ALT_URL` 当成"另一种 URL 形态"就用按键去重**——真实 `canonical_article_key` 对短链走 `s:` 支、长链走 `b:` 支（`article_identity.py:162-170`），两支永不相等 ⇒ "按 article_key 减"对这一对根本减不到。推翻依据：验证者跑出 `s:MjM5…` 与 `b:…` 两支键的实际读数。
2. **最初那条用例是恒真的**——`second.article_key = first.article_key` 把要证的等式写成了前提。规矩已回写进执行记录 §13.2：用例里凡给实现"补齐前提"的赋值，必须同时有一行断言证明它是**结论**而不是前提。
3. **最初以为"并键"要在写侧把短链行的键改成长链键**——那会把 D-V9-04 定的列语义（"本行 URL 算出的键"）改浑，并且短链首见时长链还没拿到、写不出来 ⇒ 改为只在 Diff 读侧定"收敛坐标"，列本身不动。
4. **最初准备用 `article_key` 字符串 `substr(…, 3)` 反推短链 token**——那是拿键的**外观**当解析规则，`canonical_article_key` 一改就静默分叉 ⇒ 改为 `parse_wechat_url(url).short_token`（键的算法定位仍只有 `canonical_article_key` 一处）。
5. **最初打算 `git rebase origin/main`**——被并发会话的脏文件挡住；本仓 8 个 merge 提交中有一条明写"拒绝 rebase 重写"，且 autostash 会动别人的工作树 ⇒ 改用 merge，只手工解决那一个冲突。
6. **最初把"全量本机套件"当成本步的门**——本机无 PG 且网络 connect 无上界，两轮各 20+ 分钟仍停在 81%；改为影响面回归集（21 文件，从 `grep` 的引用面**枚举**而不是挑"看着相关"的文件），全量读数交给 `@ci`。

## 7. 第二轮独立复核的结果，以及它牵出的一条真缺陷（2026-10-17 17:0x）

验证者（预算封顶 ≤30 次调用，实际 20 次）判 **PASS**，并**独立复现**了 M-1 变异读数
（关掉并键 ⇒ 恰好那 2 条红、反面用例仍绿），确认：不改写 `article_key` 列、token 取自
`parse_wechat_url` 而非手工切片、替身会话认不出查询形状时会红而不是被兜住、
三处文档（卡头 / D-V9-06 / §13）与代码现读一致且没把连库用例升格成已证。

它另给两条"强度余量"级观察，我顺着第一条追下去追出**一条真缺陷**：

- 观察原文：kb 写入侧的 `_short_link_key` 是"自家子串 + 末段切片"，与 `parse_wechat_url`
  在畸形 URL 上可能分叉，"后果是查不到映射 ⇒ 多排一次队（安全方向）"。
- 我复核后的更正：**方向不完全安全**。`parse_wechat_url` 在取 `/s/` 末段之前就有
  `host == WECHAT_HOST` 这道闸（`article_identity.py:82`），而 `kb.py:662-667` 的
  `_is_short_link` 用的是**子串**判定。于是伪装 URL
  （`https://evil.example.com/mp.weixin.qq.com/s/<tok>`）在 kb 侧能取到 token 并拿映射里
  **别人**的长链键当 `article_key` 去锚资产 ⇒ `hitCache=True` 而正文是别人的（P-3 同族）。
- 处置：`kb.py` 不在 STEP-04 的所有权内（卡面禁止修改），**只登记不顺手改** ⇒ 发布为
  **P-20**（含两条反证判据，归 STEP-02 存量兼容面 / STEP-10 详情兜底）。
- Diff 侧我自己先补一道闸的用例：`test_a_non_wechat_host_never_consults_the_short_link_map`
  ——判法用"**查没查表**"（`map_reads == 0`）而不是"结果对不对"，因为放宽入口条件的表现
  正是"结果看着也对，只是来路不明"。变异反证：把 token 改成 kb 那种末段切片写法 ⇒
  **恰好这 1 条红**（`1 failed, 3 passed`），已逐字还原（`grep MUT` 为空，工作树与动手前一致）。

我一度在 `subscription.py` 里自己又加了一遍 host 判断，写完注释才发现 `parse_wechat_url`
已经做了——**那条注释是假的**（它声称解析层"只解析、不认站"）。已回退成原写法并把注释改成
事实（指向 `article_identity.py:82`），教训与 §13.2 同族：**给实现补的每道闸都要先确认
上游有没有已经做过**，否则代码里长出第二道用不同理由实现的同一道闸。
