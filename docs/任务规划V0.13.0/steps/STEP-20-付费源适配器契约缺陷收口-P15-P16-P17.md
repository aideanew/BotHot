## 现读锚（314d7f2 复核）
| 条目 | 位置 | 现象 |
|---|---|---|
| P-15 | `app/providers/article_sources/dajiala.py:162`、`justoneapi.py:196`、`wellbyte.py:229` | `datetime.fromtimestamp(int(x), tz=None)` ⇒ 结果是**宿主机本地时区的 naive 时间**；`app/contracts/collection.py` 的 `WorkListRow.publish_time` 是 `AwareDatetime`。同仓库 `source_resolver.py:84`、`services/manifest.py:153` 已用 `tz=UTC`，说明正确写法在仓内已有先例 |
| P-16 | `app/providers/article_sources/tikhub.py:157-200`（detail）；`base.py:88-95` 契约面 | docstring 承诺"失败时降级返回 None，不抛异常"；实际只拦了 `httpx.HTTPError`（网络层），`_handle_response(..., suppress_402=True)` 对 402 以外的 4xx/5xx 仍抛 ⇒ coordinator 拿到异常而不是 None |
| P-17 | `app/providers/article_sources/wellbyte.py:223` | `item.get("source", {})` 在键存在且值为 JSON `null` 时得 `None`，下一行 `.get("dateTime")` 抛 `AttributeError` ⇒ 整页搜索结果丢失；同文件 `:142/:145` 用的是 `or {}` |

**为什么时区取 UTC、不需要裁决**：上游三家给的都是 Unix 秒（`int(x)`），Unix 秒本身没有时区歧义，`fromtimestamp(x, tz=UTC)` 是**无损**的；展示用哪个时区是前端的事，不进入采集层。⇒ 采集层统一 `tz=UTC`，与 `manifest.py:153` 同形。

## 目标（可验证的一句话）
三家 provider 产出的每一行 `publish_time.tzinfo is not None`；TikHub detail/search 遇任意 4xx/5xx 返回 `None`/空列表而不抛；WellByte 一页中混入 `"source": null` 的项时其余项照常返回。
