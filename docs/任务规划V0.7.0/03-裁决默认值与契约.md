## 4. 数据模型基线（核心实体与关系，实测字段）

```
User(sub UNIQUE String64, role String32 default 'user', status String16 default 'ACTIVE')
  ├─ 1:N Space(space.id UUID ← deps.py:65 sub→users.id 锚)
  │      ├─ 1:N KnowledgeDocument(status 至 INDEXED) ── N:1 ContentAsset
  │      └─ 1:N ContentAsset(space 维度复用，见 mark_stale_docs 跨空间判定)
  ├─ Source(type String32 'wechat_oa', external_id = biz 或 article_key)  ← F-72 的键歧义源头
  │      └─ 1:N ContentAsset  uq_asset_source_external(source_id, external_id)   [entities.py:146]
  │              字段：external_id String128, url String512, content_hash String64,
  │                   content_type String16 'article', status String16 default 'READY',
  │                   version Int default 1, quality_score, hit_count, category String32(index)
  ├─ ArticleManifest(source_id, external_id=渠道 id, status 现仅 DISCOVERED 在用)
  │      ⚠ 缺 article_key 列 → 与 ContentAsset 键空间不相交（P0-2）
  ├─ Job / JobItem(external_id, url)  ⚠ JobItem 无 manifest 外键 → 状态无法回写
  ├─ ShortLinkMap(short_key → article_key)  写入条件 final_key != short_key（kb.py:276-278）
  ├─ PushTask / PushEvent / PushLog(log_status: dead 终态) / Notification(sub 可见性锚)
  └─ HotTopic / FeedItem(三类) / DailyReport
```
软删除与生命周期：**无软删除列**（实测 entities 未见 `deleted_at`）；本版不引入（避免与 `ON DELETE CASCADE` 语义打架），过期语义走 `ContentAsset.status` + `mark_stale_docs`，删除只允许级联删除源。此项列为 NON_BLOCKING 假设 A-05，若执行者发现需要软删除必须停下上报。

## 7. ADR-0011 规范文章键（沿用 V0.6.0，未变）
```
canonical_article_key(url) -> str
  p = parse_wechat_url(url)                    # article_identity.py:54 唯一解析源
  if p.host == "mp.weixin.qq.com":
      if p.biz and p.mid: return f"b:{p.biz}:{p.mid}:{p.idx or '1'}"
      if p.short_token:   return f"s:{p.short_token}"
  return "h:" + sha256(normalize_url(url)).hexdigest()[:32]
```
- 不变量：任何输入键 ≠ `"s"`、长度 ≥ 8；同篇长链（含/不含追踪参数）→ 同 `b:` 键；同号不同 `mid` → 不同键。
- 历史兼容：规范键未命中且为短链时，旧裸 token **只读**再查一次（不改写；改写归 STEP-07）。
- 追踪参数剥离表沿用 V0.6.0 03 §2。
