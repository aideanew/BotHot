## 5. 前提与局限（本版结论只在以下前提下成立）
1. **前提 A：`apps/api/app` 自 078dc30 未变**（F-65 实测）。若执行时主干已前进，01 全部「推断（代码未变）」项需重跑核验。
2. **前提 B：V0.6.0 在 a9b194d 沙箱的读数是真实且可复现的**。本版未重跑，凡引用处均已标「a9b194d 时点值」。**若不可复现**，B-1…B-6、B-10、B-7 全部作废，M0 出门条件需重新定义。
3. **局限 1：本会话零运行验证**。没有一条连库/lint/构建/e2e 读数出自本会话；能给的只有静态读数（8 份，见 `evidence/13acacc/`）。因此「13acacc 到底几红」是 `证据不足`，不是结论。
4. **局限 2：ruff 豁免模型未完全复刻**。本会话能证明「显示宽度」模型与归档输出一致，但「行尾 URL / 单一不可断词」豁免的具体实现未独立复现（`e501_lint_scan §3` 用归档输出定性别）。执行者若 S0C.1.0 实跑与本版不符，**以实跑为准**。
5. **局限 3：需求核验到「静态锚」层级**。13–19 的成立依赖 `coverage` 里的 grep 计数与代码锚；这些能证明「无消费方/无实现」，**不能**证明「功能不好用」。可用性仍需 STEP-14 S14.4.2 / STEP-19 的运行判定。
6. **局限 4：人日估算未含沟通与生产窗口**。27.75 人日是单执行者口径；并行（§4.6）压缩的是日历不是工作量。STEP-07 的窗口与 U-02/03 的规模未知，不可外推。
7. **局限 5：本版仍含 V0.6.0 未闭合的假设**。键格式（D-V2-01）、清单对齐（D-V2-02）等仍是「默认值」而非「已签字」；01 §3 记录 20 项 0 签。裁决不落地时，STEP-02/04 的产出可被推翻，代价见 03 §1/§2 的「被推翻代价」列。
8. **局限 6：未对 V0.4.0/V0.5.0 的历史结论做二次审计**，只复核了与本版相关的条目。历史勘误沿用 V0.6.0 的做法（就地标注、不改写历史结论）。
