# 02 需求复核与辩证分析（V0.18.0，基线 main@f86811e）

## 1. 判法
P-50～P-108 中状态栏写"规划方裁定 / 未派卡 / 规划方改卡"的条目逐条终判为三类之一：
- **开卡**：仍是代码或门禁上的真实缺口，能用一条机器判据关闭 ⇒ 进 STEP-32～39。
- **追认关闭**：执行方当时的处置已经是正确答案，或卡已收口、只剩历史卡面文字与现实不符 ⇒ 追认处置、不改历史卡面（D-V18-13）。
- **延后**：真实但不阻塞 v1.1.0，且缺前提（真栈、生产数据、付费核实） ⇒ 写明启动条件。

## 3. 辩证：现在发布，还是先清完全部收尾再发
- **支持先发**：功能面与门禁面 V0.17.0 已全部收口、主干连续三绿；剩余卡全是门禁精度与测试卫生，对用户可见行为无影响；291 个提交不发版，CHANGELOG 只会继续失真。
- **反对先发**：P-97（RSS 回退重试重复排队）是行为缺陷。复算其后果：只在清单被合法回退时发生，代价是一次重复排队与缓存命中，不重复建资产、不花钱——不阻塞。
- **不能先发的两条**：P-107（公开仓库的日志里能读到密钥值）与 P-62（422 把调用方的凭据写回响应和日志）都属于"敏感信息不出进程"不变量，发布等于把它们写进版本。
- **终判**：先修 32、33，三绿后发 v1.1.0；其余卡进 v1.1.x。
