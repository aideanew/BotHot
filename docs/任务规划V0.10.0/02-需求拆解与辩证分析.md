## 2. 岔口的辩证裁决（D-V5-01）
- **正题**（先补读数）：没有真库 0 failed，R0/16 只能算已实现；UI 建在没验过的地基上。
- **反题**（先开 UI）：UI 是用户三次点名的核心，已被环境问题拖了三个版本。
- **新读数改变了两边的前提**：①CI 有 PG service 和 skip 门，连续 4 次绿，「0 failed」已有机器读数，正题要的东西已经存在；②本机前端依赖本就就绪，反题担心的「在共享工作树装依赖」不需要发生。
- **合题**：不是二选一，而是**两条线并行**：规划方走 UI 关键路径（14a → 15 → 14b），执行 Agent 走 00S（Security 回绿）与 RV 剩余手测。两条线允许修改的路径交集为空（04 §4），满足并行四条件。

## 3. 另外两对矛盾
1. **「环境读数」与「机器身份」**：V0.9.0 说 node_modules 不存在，本版说存在，两者都真，因为是不同机器。合：环境读数必须带主机标识，不跨机器继承（00E 变更节）。
2. **「门禁严」与「门禁可过」**：gitleaks 规则正确，但历史命中不能靠打码消失，只能靠登记。合：HEAD 打码 + `.gitleaksignore` 用与 CI 同版二进制产出的指纹，每行注释「占位、非真实凭据」；一旦发现真实凭据，立即停下并轮换。

## 4. 根因链（当前基线）
- **RC-1 Security 连续红** ← 无 `.gitleaksignore` ← 上版判定「本机无同版二进制，不能猜指纹」← 现已不成立（F-05）。
- **RC-2 UI 三版未动** ← 归属待签 + 环境不确定 ← 两者本版均解（D-V3-00 已授权，F-08~F-10）。
- **RC-3 裁决 0 签** ← decision-log 不存在（F-11）← 00G 未执行。
- **RC-4 引擎空洞、管理端 0 消费、SLA 无基线**：同 V0.9.0，未变。
