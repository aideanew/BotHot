# 02 需求复核与辩证分析（V0.22.0）

## 1. 复述
BotHot 是 Aidean 主平台的独立机器人子系统：多渠道推送、热点日报、知识库 + RAG 问答、公众号入库、整号订阅、SSO、管理后台。
截至 v1.1.4，功能面八条里六条"已实现"，两条"部分"（005、008），差的都不是功能代码，而是**真后端端到端从未被执行**；
另有一条契约尾巴（MeWallet）和三处过期判词。本版不新增功能。

## 4. 5W1H（精简）
- **What**：两条"部分"需求缺的是运行环境不是代码；一条契约尾巴；三处过期判词。
- **Why**：真后端 e2e 依赖 Compose 全栈 + OIDC 白名单 + 真 LLM（`real-backend.spec.ts` 头注释），CI 三者皆无 ⇒ 一直 skip。根因是**把"登录"与"已登录后的功能"绑在一起**：功能路径只需要一条有效会话。
- **Where/When**：`.github/workflows/ci.yml` 新 job；`scripts/e2e/`；`apps/web/e2e/`、`playwright.config.ts`。59 先于 60（共用 job）；61 与 59/60 文件不相交可并行；62 等三者读数；63 最后。
- **Who**：59/60/61 规划方；62/63 执行助手；判定由独立复查子智能体（只看 diff + 运行结果）。
- **How**：Redis 写会话 + PG 写 users 行（role=admin）→ uvicorn 3300 → `next build`（MOCK=false）在 3200 → Playwright 带 cookie；LLM 指向本地假 SSE 上游。
- **What if**：① `/auth/me` 降级分支不放行 ⇒ 方案 B（见 §5）；② Redis 键前缀与代码不一致 ⇒ 种子脚本从 `session_store` 导入常量而不是手抄；③ 端口被占 ⇒ 报错不换口（D-V4-02）；④ 假上游格式漂移 ⇒ 假上游按 `app/services` 现有 SSE 解析器的单测样例写，不自造格式。

## 5. 钢人论证与条件方案（STEP-59 会话注入）
- **支持**：会话记录结构在 `session_store.py:17-45` 公开且可序列化；角色只读本地 `users.role`；主平台不可达有显式降级（`service.py:220-280`）。
- **反对**：① 写 Redis 绕过了 SSO 回调本身 ⇒ SSO 链路不被这条 e2e 证明（**成立**，不声称证明，SSO 由 `test_auth.py` 系列单测承担，C1 留外部）；② 降级分支可能把 `is_admin` 置 false ⇒ 四屏仍不可达（**未排除**，S59.0 探针判）。
- **方案 A**（默认，2026-10-27 19:46 修订）：收编 `apps/api/scripts/qa_seed_sessions.py`（`qa-fixture-` 令牌命中 `service.py:226-237` 短路，不进主平台），uvicorn 显式 `SESSION_STORE_BACKEND=redis`。
- **方案 B**（S59.0 红时）：e2e 档起一个本地假主平台（userinfo/wallet 两个端点，返回固定 JSON），不改产品代码。
- **共同部分**：job 骨架、端口、假 LLM、Playwright 配置。**分叉点**：S59.0 读数。不需用户裁决。
