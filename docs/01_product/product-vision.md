# Product Vision — BotHot

## 一句话愿景

> **让信息从「发现」到「触达」全链路自动化：公众号链接入库 → 知识库 RAG 问答 → 热点聚簇 → 多渠道机器人定时推送，形成信息源知识库机器人闭环。**

## 为什么存在

信息工作者面临一个反复出现的问题：

1. **信息散落**：公众号文章分散在微信生态内，无法统一检索、关联、复用。
2. **知识不可问**：即使收藏了文章，也无法对内容进行自然语言问答。
3. **触达被动**：有价值的信息无法主动推送到工作群（飞书/钉钉/企业微信），只能等人去翻看。
4. **热点不感知**：大量文章涌入后，哪些在说同一件事、哪个话题在升温，全靠人工判断。

BotHot 把这四个痛点串成一条闭环：

```text
公众号链接 → 采集入库 → 知识空间(RAG) → 热点聚簇 → 多渠道定时推送
     ↑                                                    │
     └────────────── 整号订阅自动发现 ←────────────────────┘
```

## 与 AideanBot 的关系

BotHot 是 AideanBot 的全面升级版：

| 维度 | AideanBot | BotHot |
|---|---|---|
| 定位 | 知识库管理平台 | 多渠道机器人推送 + 知识管理平台 |
| 推送能力 | 无 | 6 种渠道主动推送（飞书/钉钉/企业微信/微信 ClawBot/Webhook/站内）✅ 已实现 |
| 热点能力 | 无 | 热点聚簇 + 热度评分 + Feed 流 + 每日日报（融合 AIHOT） |
| 知识库 | ✅ 保留 | ✅ 继承（公众号入库 + LangBot RAG + 知识空间 + 整号订阅） |
| 前端端口 | 3333 | 3200 |
| 后端端口 | 8000 | 3300 |

## 用户画像

1. **信息运营者**：需要把公众号内容结构化管理、主动推送到工作群的人。
2. **团队管理者**：需要每日热点日报、信息流浏览来掌握行业动态的人。
3. **知识工作者**：需要对入库内容进行 RAG 问答、知识检索的人。
