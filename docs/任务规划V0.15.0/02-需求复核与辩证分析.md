- **终判（D-V12-03）**：接，但必须先给 `guards.py` 加显式基线（环境变量 `GUARD_BASE`，CI 传 `github.event.before` / PR base sha）；CI 内 rc=3 视为失败（CI 不允许第三态）。gitleaks 那一步在 CI 的 backend job 里可以跳过（Security 已覆盖），以 `SKIP` 读数记账。`scripts/entry.py`、`scripts/check_entry_parity.py` 并入 Agent-Guard 写入面。

## 7. P-37：gitleaks 在 Windows 上 fail-open
- **What**：Git for Windows 的 system 级 `*.docx diff=astextplain` + 没装 `docx2txt` ⇒ `failed to scan` 却 rc=0。
- **证据**：仓库 `.gitattributes:42` 已有 `*.pdf binary`，但没有 docx；`git ls-files '*.docx'` = 2。
- **钢人（①装 docx2txt）**：依赖每台开发机的手工安装，不可复现。
- **钢人（③Windows 也跑 gitleaks 并比对）**：成本高，而且 CI 的 Windows runner 同样带 system gitattributes。
- **终判（D-V12-06）**：选 ②——`.gitattributes` 追加 `*.docx binary`（与既有 pdf 行同形），仓库级覆盖 system 级 textconv。门侧把 `failed to scan` 判为 rc=3 的收紧**追认并保留**作纵深防御。验收：@win 上 `make evidence-check` 在非空批 rc=0。

## 8. P-38：墙钟上界用例在负载下假红
- **What（执行方）**：二选一——A 独占复跑约定；B 比值判据。
- **实测（F-V15-02）**：断言对象是整段 import；上界 8.0 = 3+5 把嵌套超时重复相加，又对 import 开销零余量。独占 ×3 全过（6.5s 墙钟），可达库 import 1.0～1.2s。
- **钢人（A）**：最便宜。反对：把判据可靠性交给“人记得独占”，下次照样会有人去改阈值。
- **钢人（B）**：比值需要每次测一次无界基线（45s 不返回），测试时长不可接受。
- **终判（D-V12-07，第三条路 C）**：子进程只对**探测段**计时，上界 7.0s、下界 3.0s；import 总耗时继续自报但不进判据。
  - 计时点：`app/main.py:242` 以模块属性 `asyncio.run(...)` 调探测，子进程在 `import app.main` **之前**把 `asyncio.run` 换成计时包装（进入时起表、返回或抛出时停表，自报 `SCHEMA_PROBE_SECONDS`），不碰 `apps/api/app/**`。
  - 上界理由：探测段 = 引擎创建 + `wait_for(5.0)`（`main.py:188`）+ 超时后 `engine.dispose()` 与 loop 收尾，后两者在 `wait_for` 之外，故取 5.0 + 2.0 余量；黑洞下实际走 `connect_timeout=3`（`:187`）先抛的分支，约 3s。
  - 子审查纠正：只把 `wait_for` 改大的变异**红不了**（3s 的 connect_timeout 先触发）；变异必须同时放大两个常量（3→20、5.0→30）。
  - 这是判据变更，由本裁决落文，执行方实现。
