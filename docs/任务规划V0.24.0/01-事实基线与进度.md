## 2. 已确认的事实（逐条带锚）

### 2.1 契约侧：八态是「全局词表」，不是「每视图 8 个」

| 事实 | 证据 |
|---|---|
| `definitions.State.enum` 恰 8 值 | `ux_states.schema.json#definitions.State`（`initial/loading/empty/success/error/forbidden/unauthenticated/degraded`） |
| 同处写 `"x-required-for-every-core-view": true` | 同上 |
| 同处 `note` 写「8 态而非 5 态」 | 同上 |
| 6 个视图实际只列 5–7 个键 | `/spaces` 7、`/hot` 5、`/chat` 5、`/admin` 6、`NotificationBell` 6、`/onboarding` 2 |
| `NotificationBell` 多一个 enum 之外的 `offstate` | 同上，`:91` |
| `x-universal-rules[4]` 写「新增核心 view 必须一次交齐 8 态」 | 同上 |

⇒ **四处互斥**：enum 8 值 + 「每视图必交 8」+ 各视图 5–7 键 + `offstate` 不在 enum。P-147 登记的就是这一条。

### 2.2 `/chat` 契约只要求 5 态

`x-core-views[/chat 流式问答].states` 逐字：

```
loading          首 Token 前显示「思考中…」占位 + 可中断按钮
success          增量渲染，含引用来源列表
error            流中断必须保留已渲染内容 + 「连接中断，可重试」，禁止清空重页
unauthenticated  跳登录，保留提问草稿
degraded         30002 LANGBOT_API_ERROR / 50002 ⇒ 回落非流式或提示不可用；
                 超时锚 LLM_FIRST_TOKEN_TIMEOUT 触发时给「响应较慢」而非静默
```

**没有 `initial` / `empty` / `forbidden`。** 而 `apps/web/e2e/r19-chat-stream.spec.ts:27-36` 手抄的是那 8 值 enum，`:107` 断言 `toHaveLength(8)`——它把「全局词表」当成了「本视图要求」。

## 4. 本轮被推翻的三条既有结论

**① P-150 的第二句「`/chat` 那句『保留提问草稿』在两档下都不成立（`useSseAsk.ts:152` 一带清草稿）」——不成立。**
`useSseAsk.ts:152` 的 `setInput("")` 在 `ask()` 内部（`:147-163`），语义是「**已发出**的提问清空输入框」，不是「会话失效清草稿」。会话失效走 `:118-121` 的 `onUnauthorized()`，而 `page.tsx:46` 传的是空函数，`reset()` 不被调用，`input` 保持原值 ⇒ 未发出的草稿**不会**因 401 丢失。契约该句已兑现，本版不给它开卡。

**② 「`/chat` 需要 8 个态」——不成立。**
契约逐视图只列 5 个。`initial` 在 `/chat` 无专属 DOM 出口（只有 Next 路由骨架），`forbidden` 无 403/10004 分支（越权 chat 返 404+30004，`chat.py:431-434`）。要求 8 个就是造需求。

**③ 「先等 `e2e-real` 绿再开 60」——不可达。**
`e2e-real` 近 40 个提交从未 success（早期作业不存在 → `skipped` → `failure`）。判据改为「真栈可起」+ 只看 60 自己那一步。
