## 2. 推送失败的真实原因（不是网络）

三次尝试，逐次读数：

| 尝试 | 命令 | 读数 | 判读 |
|---|---|---|---|
| 1 | `GIT_TERMINAL_PROMPT=0 git push` | `schannel: failed to receive handshake, SSL/TLS connection failed` | **网络层**：直连 GitHub 握手不过 |
| 2 | 同上 + `https_proxy=http://127.0.0.1:10808` | `could not read Username for 'https://github.com': terminal prompts disabled` | **凭据层**：代理已通、TLS 已过，卡在用户名 |
| 3 | 凭据面排查 | `credential.helper=manager`；无 `gh`；无 `GH_TOKEN`/`GITHUB_TOKEN`；无 `~/.netrc`；无 `~/.ssh/*.pub` | **无任何可用凭据** |

⇒ 不是「连不上」，是「连上了但没有身份」。`credential.helper=manager` 已配置但里面没有已保存的 GitHub 账号。

## 6. 为什么没有 zip 之外的第二条兜底

- **不 force push**：Skill §8 明令禁止。
- **不写凭据进文件**：Skill §0 第 4 条（秘密永不写入任何文件/日志/提交）。所以本文档里不出现任何 token、也不给「把 PAT 写进 remote URL」的做法。
- **不改 `git config` 全局代理**：用户 2026-10-28 明确「不要改全局 git config」，本轮的代理只在单条命令的环境变量里生效。
