# 需求文档

> 版本：v0.3（v0.2 基线 + R7.6 采集通道改为后台可配置，回写 §六 层③） | 更新：2026-09-28
> 用户故事与验收标准；技术方案见各 ADR 与开发计划

## 一、产品目标（源自 README，五条）

1. 用户通过机器人发送**公众号链接**到服务器端，自动构建知识库，知识库自动更新即时生效
2. 用户选择入库方式：(1) 该公众号全部文章；(2) 链接中这一篇独立文章
3. 机器人可由后台控制主动发送消息给用户（用户端默认开启）
4. 【未来】抖音/B站/小红书等其他信息源
5. 【未来】视频解析仅 pro/max 会员（按视频长度消耗积分）

## 二、M1 用户故事（单篇闭环）

| # | 故事 | 验收标准 |
|---|---|---|
| U1 | 作为用户，我在 Web 对话框发送公众号链接 | 系统识别来源并返回选择卡片（单篇即时入库/整号自动采集） |
| U2 | 我选择"仅本篇" | 数秒内收到进度与完成回执；文章入当前知识空间 |
| U3 | 我提问文章内容 | 得到基于该文章的**带引用**回答 |
| U4 | 我创建多个知识空间 | 空间间内容完全隔离（M0 已实证底层保障） |
| U5 | 我用 Aidean 账号登录 | SSO 跳转登录，无需二次注册 |

## 三、M2 用户故事（整库+订阅+微信）

| # | 故事 | 验收标准 |
|---|---|---|
| U6 | 我选择"导入整库" | 显示预计篇数；批量导入，进度实时；部分失败可重试（PARTIAL_SUCCESS） |
| U7 | 公众号发布新文章 | 定时自动同步入库，即时可检索，无需任何手动操作 |
| U8 | 我在微信发链接给机器人 | 与 Web 相同的完整闭环（绑定流程 + 主动消息回执） |

## 四、非功能需求

- **安全**：密钥只入 env；SSO state 强校验；余额不落库（铁律见 ADR-0002）
- **SSO 信任边界（R3.2，2026-09-23 扩写）**：AideanBot 是主平台内嵌应用，SSO 信任边界为 `oidc_issuer`（主平台 OIDC），非第三方开放授权码流程。`userinfo` 端点为权威身份来源；`iss`/`aud` 可选校验（`oidc_issuer_expected`/`oidc_audience_expected` 配置非空时生效）；PKCE 不启用（session cookie 派生机制已覆盖威胁面，见 `service.py` docstring 裁定 R5.B）。
- **即时生效**：入库即可检索（Chroma 在线 upsert，M0 已实证）
- **成本控制**：Redfox 清单 Redis 缓存；直抓限流 throttle
- **多主题**：前端永远浅色、中文（对齐主平台铁律）

## 五、明确不做（当前版本）

抖音/B站/小红书源、视频 ASR、积分体系、多机器人平台直连（均 M4+，架构已预留）

## 六、采集方式三层语义（R7.5.2，F-28 口径澄清）

> 根因：EngineSwitcher 切换的是知识库引擎（builtin/coze/dify/fastgpt），不是采集方式。
> 用户/开发者可能误认为「切换采集方式」是已支持或计划支持的功能。以下三层语义
> 明确界定当前能力边界，消除歧义。

| 层 | 语义 | 当前状态 | 代码证据 |
|---|---|---|---|
| ① 入库范围 | 单篇 / 整号 / 批量粘贴 / 公共库拷贝 | **已支持** | `kb.py:165` ingest_url / `batch_ingest.py:72` submit_batch / `subscription.py:142` sync_account / `public_library.py:105` copy |
| ② 源类型 | wechat_oa / web（占位） | **仅 wechat_oa** | `source_resolver.py:24` ALLOWED_HOSTS={"mp.weixin.qq.com"}；`entities.py:60` web 为 M4 占位零消费者 |
| ③ 采集通道 | RedFox API / 自建 | **仅 RedFox 已实接；通道改为后台可配置**（R7.6，2026-09-28） | 渠道注册表 `app/providers/discovery/registry.py`：`redfox` 已实接，`rss` 已注册为**未实接占位**（`implemented=False`，`available` 恒假，永不入选）；`discovery_channels`（启用白名单）+ `discovery_default_channel` 后台可配，就绪度查 `GET /api/v1/admin/discovery/channels`；**第二渠道尚无实接** |

**关键裁定**：用户不可切换采集方式（源类型和采集通道均为系统级配置，非用户可选项）。
EngineSwitcher 的切换对象是「知识库引擎」（问答侧），与采集方式完全正交。
前端已写死「公众号 biz 或 profile URL」输入提示（`subscriptions/page.tsx:220`），
无源类型/通道切换控件，且已裁定不做（R6.6.6 裁定维持）。

> 该表述在 R7.6 后已不成立——通道选择已从代码硬编码改为后台可配置项，且已注册 `rss`
