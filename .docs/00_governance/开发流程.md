# 开发流程规范

> 版本：v1.1 | 更新：2026-09-24 | R6.5.3 新增「结论写入前核对闸」

## 一、六步循环（每个原子任务的执行纪律）

```
文档 → spec → 实现 → 测试 → 回写 → 摘要
  │      │      │      │      │      └─ 关键决策记入 memory/ADR
  │      │      │      │      └─ .docs 对应文档同步更新
  │      │      │      └─ 单测/集成测试随任务交付（不单列测试任务）
  │      │      └─ Route 不写业务逻辑；providers 是外部系统唯一防腐层
  │      └─ 接口契约先行（请求/响应/错误码登记表）
  └─ 动代码前先读《文档索引》与相关 ADR
```

## 二、仓库结构

```
backend/   FastAPI（app/api/v1 | core | services | providers | repositories | models）
frontend/  Next.js App Router + TS + Tailwind
docker/     compose 全家桶 + .env 体系（密钥只入 env）
.docs/      文档真源（本规范所在）
.trae/      计划文档（执行基准）
```

## 三、提交纪律

1. **提交前移除**：测试脚本、临时报告、`.trae/tmp/` 全部内容
2. **历史新增代码补注释**（中文，说明 why 而非 what）
3. 提交信息：`<scope>: <what>`（如 `models: v1 schema`、`docs: ADR-0002`）
4. 新架构决策 → 先补 ADR 再动代码

## 四、质量门禁（CI 三 job）

- backend：ruff + pytest（`backend/` 下 `ruff check app tests && pytest tests/ -q`）
- frontend：typecheck + build（`npm run typecheck && npm run build`）
- compose：`docker compose -f docker/compose.yml config --quiet`

## 五、环境启动

```bash
cp docker/.env.example docker/.env   # 首次：填入密钥
docker compose -f docker/compose.yml up -d
# backend 本地开发：
cd backend && python -m venv .venv && .venv/Scripts/pip install -e ".[dev]"
.venv/Scripts/python -m uvicorn app.main:app --reload --port 8000
```

LangBot 首次需经 WebUI(:5300) 初始化管理员并安装 LangRAG 引擎（步骤见 M0 报告 §四）。

## 六、外部依赖变更处理

外部系统（主平台/LangBot/Redfox）契约变化时：
1. 先在 `.trae/tmp/` 写最小验证脚本实证
2. 更新 M0 实证报告对应章节（追加"复验记录"）
3. 触发 ADR 修订（不推翻骨架，记增量）

## 结论写入前核对闸（R6.5.3）

每条 R 项 / F 项必须带 `file:line` 锚点，无锚点不得写入。锚点写入时必须实读一次（grep/read），不得凭记忆或采信他人结论。
