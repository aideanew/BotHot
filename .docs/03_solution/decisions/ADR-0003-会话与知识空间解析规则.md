# ADR-0003：会话与知识空间解析规则

> 状态：已采纳 | 日期：2026-09-04 | 来源：两份开发计划评审共同发现（WorkBuddy Q2 / OpenCode Q6，裁决见《评审报告-开发计划交叉裁决.md》W7/O6）
> 决策级：产品规则（填补 M1 对话流实现前的决策空洞）

## 背景与决策驱动

系统领域模型为 `User → KnowledgeSpace(多) → 内容`，对话流必须回答：**一次会话提问时，从哪个（哪些）知识空间检索？** 此前两版计划均未显式定义，导致 T1.10（对话流）无法实现。

## 决策

**默认仅检索「当前选中空间」；提供消息级显式「全部空间」开关；提供空间切换命令词。**

### 规则细则

1. **会话状态**：每个会话（session_id，Web 或 IM 通道同构）持有 `active_space_id`（用户级会话属性，持久化于 AideanBot 侧）。
2. **默认行为**：普通提问 → 仅在 `active_space_id` 对应的 LangBot KB 检索。
3. **显式开关**：消息以 `#全部` / `#all` 前缀（或 UI 开关）→ 聚合该用户全部 ACTIVE 空间检索。
4. **切换命令**：`/空间 <名称>` 切换 `active_space_id`；`/空间` 列出全部空间并标注当前。
5. **建库归属**：对话中发起新链接建库 → 入当前选中空间（无空间时引导先创建）。

## 备选与否决

| 备选 | 否决理由 |
|---|---|
| 永远聚合全部空间 | 隐私与噪声双输：跨空间内容混入回答违背用户"分空间管理"的心智；token 成本随空间数线性涨 |
| 按消息来源自动路由 | 不可判定：消息内容无法可靠推断目标空间，误路由不可解释 |

## 实现约束（M1 T1.10）

- 与多 KB 路由方案 A（每空间一组 bot+pipeline，见 ADR-0002 增补）协同：`active_space_id → 对应 pipeline 的 bot_uuid`，切换空间即切换 sync 调用目标。
- `#全部` 模式：逐空间并行调 retrieve 后合并（相似度排序取 top-k），或临时聚合 pipeline（实现时二选一，倾向前者——无 LangBot 侧状态）。
- 引用溯源需带空间标识（回答标注来源空间名）。

## 影响

- M1 T1.10 对话流按此实现；前端聊天页需呈现当前空间上下文与切换入口。
- 数据模型无变更（会话属性存应用层，不新增表；如后续需要持久化可加 `conversation_states` 轻表——M1 先用内存+会话 Cookie 承载）。
