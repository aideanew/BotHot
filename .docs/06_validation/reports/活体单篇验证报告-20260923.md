## 三、R0.7.2 图片过滤与防盗链实测

### 3.1 白名单过滤有效性（非空判定）

大纲原假设是「过滤是否被防盗链拦截」，但更该先问的是**过滤器是否在真的干活**——空结果既可能是「剔干净了」也可能是「无图可剔」。故先做逐标签审计。

**CANONICAL（提取器收录 0）**：原文全文 9 个 `<img>` 标签，剔除理由逐条可判读——

| 剔除理由 | 数量 |
|---|---|
| src/data-src 为空（JS 懒加载占位） | 5 |
| 非 URL 形态（JS 模板残片 `'".concat(l[` / `EMOJI_BLANK_IMG`） | 2 |
| 非受信图床 `res.wx.qq.com` | 1 |
| **mmbiz 但位于隐藏区块** | 1 |

最后一条是关键：全文**唯一**的 mmbiz 图位于 `js_jump_wx_qrcode_dialog`（`display:none`）内、`qrcode-con` → `jump_wx_qrcode_img` 路径上。该篇正文**本就无图**，0 图片是隐藏节点过滤的正确结果，**不是提取缺口**。

**IMAGED（提取器收录 14）**：原文全文 23 个 `<img>` 标签 → 14 收录 / 9 剔除；mmbiz 域共 15 个，其中 14 个在正文可见区被收录，1 个位于隐藏/二维码/底部工具区块被剔除。域名分布 `{(空/非URL): 3, mmbiz.qpic.cn: 15, res.wx.qq.com: 1}`，**提取器输出域名分布 `{mmbiz.qpic.cn: 14}`**——输出集为纯 mmbiz，白名单无泄漏。

### 3.2 防盗链实测（R0.7.2 原问题）

取 IMAGED 的 14 张正文图前 6 张，按 4 组请求头真实 HTTP 下载，判定口径 = HTTP 状态码 + Content-Type + 图片魔数（PNG/JPEG/GIF/WebP/RIFF）：

| 组别 | 请求头 | 结果 |
|---|---|---|
| A 裸请求 | 无 UA、无 Referer | 6/6 HTTP 200，`image/png`，魔数全合法 |
| B 桌面 UA | 无 Referer | 6/6 HTTP 200，同上 |
| C 微信 UA | 无 Referer（本项目 fetcher UA） | 6/6 HTTP 200，同上 |
| D 微信 UA + 文章页 Referer | — | 6/6 HTTP 200，同上 |

字节数在四组间**完全一致**（img1 74,887 / img2 150,512 / img3 56,048 / img4 54,102 / img5 17,021 / img6 9,802 B），说明响应与请求头无关。

**裁定：mmbiz.qpic.cn 对本样本的图片 URL 无防盗链策略**——连裸请求都能取回完整 PNG 二进制。大纲「验证引用/下载是否被微信防盗链策略拦截」的担忧在本样本上**不成立**，不构成实现阻塞。

附带观察（本样本未触发，仅作登记）：`_TRUSTED_IMG_HOST` 判断是子串匹配，因此 `http://mmbiz.qpic.cn/...` 与 `https://mmbiz.qpic.cn/...` 同样会被收录；本批提取输出的图片全为 `https://`，CANONICAL 那张 `http://` 图因位于隐藏区未被输出，故 http 明文图能否跨协议取回**未实测**。

## 四、质量评分口径复验

三篇样本分别落在阈值 30 的 2.7 / 2.7 / 3.3 倍，评分分布合理且扣分理由可观测：

### 5.2 LangBot 契约补正（对 M0 §四 的四处修正）

安装路径此前**完全无文档**，以下口径均由运行中容器源码反查 + 实测得到：

1. **`/api/v1/user/init` 的 body 字段是 `user`，不是 `email`**——传 `email` 直接
   `KeyError: 'user'`（`groups/user.py:78` 读 `json_data['user']`）。M0 §四 B-T8
   勘误 1 只记了**登录**接口的字段，init 是同一个坑的另一处。
2. **业务错误不是 HTTP 4xx**：LangBot 惯例为 **HTTP 200 + body `code ≠ 0`**。
   以 HTTP 状态码判成败会漏掉全部业务失败。
3. **插件路由前缀是 `/api/v1/plugins`**，不是 `/api/v1/plugin/app`——后者全 404。
4. **异步任务状态在 `data.runtime.{state, done, exception, result}`**，不在顶层
   `state`。按顶层读会全程得 `None`，本次因此空跑 10 分钟才定位。

另：市场安装任务最终 `state=FINISHED` 但带
`Action apply_plugin_installation call timed out` 异常——与 M0 §四「主侧超时、依赖
按 artifact+指纹缓存、重试秒过」的既有登记一致，**是已知行为不是失败**。故安装成功
判据取**引擎在位**（`GET /api/v1/knowledge/engines` 非空），而非「任务无异常」。

### 5.3 ingest → retrieve（生产 client 全链）

以 `langbot_format`（非自行拼装 markdown）上传 → 触发 ingest → 文件清单轮询至
`completed`，随后**双向对照检索**：

- 正例（向量 / 全文 / 混合）：命中且**内容归属正确**；
- 反例（无关的量子物理查询）：仍返回 3 条最近邻——**符合预期**。Chroma top_k 无
  阈值、恒返最近邻，故隔离性的判据是「内容归属」而非「命中数」。

**检索结果契约修正**：顶层键为
`['content','distance','id','metadata','score']`——**字段是 `score`/`distance`，
不是 M0 §四写的 `similarity`**。内容块键
`['file_base64','file_name','file_url','image_base64','image_url','text','type']`，
其中 **`file_name` 等于 upload 返回的 file_id**——这正是 `chat.py:382` 取引用标题的
锚点，引用链的数据契约因此成立。

附注：`backend/tests/test_chat_sse.py:_StubLangBot` 仍带 `"similarity": 0.92`，与真实
契约不一致。引用代码从不读 similarity，**不影响功能**，但属已知的桩保真度偏差。

### 5.5 测试侧陷阱：TestClient 跨 event loop（非产品缺陷）

初版脚本用 `TestClient` 驱动，得到 `HTTP 200` + 单帧
`error{code:50001,message:"内部错误"}`；改为让依赖在 app loop 内惰性构造后变成
`HTTP 500` 的 `TypeError` 信封。根因是 **TestClient 在独立 event loop 起 ASGI app**，
与外层创建的 SQLAlchemy session / httpx 客户端**跨 loop 复用**会抛
"attached to a different loop"，被 `chat.py:403` 的 catch-all 归一成 50001。

三组对照把窗口压到可判读：

| 组 | 驱动方式 | 结果 |
|---|---|---|
| 单 loop 直调 `ask()` | 同 loop，session/client 同源 | 51 帧，meta + 真实引用 + done ✅ |
| TestClient + 外层 session | 跨 loop | 19 帧，HTTP 200 ✅ |
| TestClient + app-loop 惰性依赖 | 跨 loop（构造时机错） | 500 `TypeError` ❌ |
| **`httpx.ASGITransport` 同 loop** | 同 loop | **HTTP 200，meta→delta×58→done ✅** |

**判据**：产品代码未改一字，失败随 harness 改动消失。最终采用
`httpx.ASGITransport` 在同一 loop 内驱动 ASGI app，一次通过。

### 5.6 上游瞬时抖动（真实鲁棒性观察，登记而非修）

一次 `resolve()` 返回
`SourceUrlUnrecognizedError [20001] 页面不是公众号文章（锚点缺失）`，**重试即过**。
这是微信侧反爬的瞬时抖动，非代码缺陷——但**单篇抓取路径当前无重试**，批量场景
（`scheduler/job_worker`）会放大该概率。登记为 **R2.1 附带观察项**。
