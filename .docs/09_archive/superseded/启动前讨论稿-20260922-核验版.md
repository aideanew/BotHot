## 二、核心六问

### 1. 有哪些采集方式？—— ◐ 4 条链路，3 通 1 断

| 采集方式 | 判定 | 证据（file:line） |
|---|---|---|
| ① 单篇链接采集 | ✅ | `POST /api/v1/spaces/{id}/docs`（202）→ 轮询 status；域名白名单 `ALLOWED_HOSTS = {"mp.weixin.qq.com"}`（source_resolver.py:24）；活体证据 09-13：ingest 202 → 5 秒 READY → SSE 带真实引用 |
| ② 批量粘贴多篇 | ✅ | 前端 api.ts:745 `parseBatchUrls` 按换行切分 + AddArticlePanel.tsx:220 逐篇串行 await；**后端无批量端点**（纯前端循环） |
| ③ 公共库引入 | ✅ | `GET /spaces/public` + `POST /spaces/{id}/links` copy 式转入、幂等 skipped（public_library.py:61,92） |
| ④ 整号订阅采集 | ◐ 断链 | 端点 6 个在（subscriptions.py:45-138，注册于 main.py）、模型 5 层在（Source/Subscription/Job/JobItem/ArticleManifest）；但 RedFox `query_work_list` **零生产调用方**（仅 client.py 与测试命中）、**无 job_worker/scheduler**（jobs.py:3 仅注释；compose 仅 postgres/redis/langbot/backend/frontend，无 worker 服务）、JobItem 建后停 PENDING 无人消费 |

前端已自我声明该限制：AddArticlePanel.tsx:344「当前仅支持单篇公众号文章链接（mp.weixin.qq.com），整号批量入库暂未开放」。

### 2. 是否支持用户切换采集方式？—— ◐ 分入口，无统一切换

- 单篇/批量/公共库引入在空间详情页（AddArticlePanel / PublicLibraryPicker），整号订阅在独立页 `/subscriptions`，首次引导走 onboarding 三步三来源卡（onboarding/page.tsx:24-34、256-280）。
- **无**「按链接 / 按公众号」Tab 切换器；需求文档 U1 原设计的「仅本篇 / 整库[置灰]」选择卡片未实现。
- 对策：N4/N6 采集方式统一入口（挂阶段 5，见 §六）。

### 3. 是否支持采集某个公众号的所有文章？—— ❌

即上表 ④ 断链。完整执行闭环缺**四环**：RedFox 清单实拉（1.1.2）→ Manifest 同步与 Diff（1.2）→ Job 执行器（1.3）→ 增量调度器（1.4）。
**硬阻塞**：RedFox 账户积分 0.0（09-19 活体对照实验：Key 有效、错误码 3201 余额不足，单次调用 0.4 积分）——属用户侧充值动作，非代码问题（→ D3）。

### 4. 是否支持只采集一篇文章？—— ✅ 完整闭环且经真实活体验证

单篇 MVP 全链 `resolve → extract → POST /docs(202) → 轮询 READY → SSE ask`；活体证据：09-13 C-T7 终验 ingest 202 → 5 秒 READY → SSE 帧序 meta/citations/delta×12/done，引用带真实文章标题（台账 `fleet_ct7_full_chain_20260913.txt`）。幂等与质量分链路齐备。

### 5. 是否支持绑定主流知识库（ima / 飞书·扣子 / Notion 等）？—— ❌ 无任何集成，语义需裁决

- 实测：`ima|feishu|lark|notion` 在 backend/app 与 frontend 全部业务代码中**仅命中 1 处注释**（EngineSwitcher.tsx:8「notion 按 CMS 对待，不进引擎位」），零实现代码。
- 现状不是"知识库绑定"，而是 **RAG 引擎位**（5 槽）：`builtin`(LangBot) 唯一真实可用；`main`(RAGFlow)/`coze`/`dify`/`fastgpt` 六方法全 `NotImplementedError`，`ENGINE_IMPLEMENTED` 注册表仅 builtin=True（engine_port.py，R1 三条件口径）。
- 既有裁决：Notion 按 CMS 导出归档目标对待、未实施；ima/飞书零设计覆盖。
- **三种语义对应三套完全不同的工程**（A. RAG 引擎位检索 / B. 导出归档目标 / C. 采集来源），必须先裁决主语义（→ D1），未裁决前相关方向零开发。

### 6. 文章是否有分类？是否支持免费的公共信息输出？—— 分类 ❌ / 公共库 ◐

- **分类**：不存在。entities.py 无 category/topic/tags 任何字段；前端零分类 UI（G6，阶段 3.4 立项待做 → D5）。
- **公共库**：后端已实现非占位（`GET /spaces/public` + copy 式引入幂等）；但 **`is_public` 无任何写端点**（只能 SQL 手工置位，完全不可运营）；前端 `/public` 是 36 行壳页（数据加载后从不渲染）且全站零导航入口。
- **免费**：需求文档 §五明确"积分体系不做"→ 无计费层，站内引入天然免费；但**对外公共信息输出渠道（公开页 / 公开 API / 推送）完全不存在**（→ D5）。
