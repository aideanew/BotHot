## 裁定 1：镜像重建授权（R6.1.2 · P0 止血）

### 背景
运行中 backend 镜像落后 HEAD 6 个后端提交，含：
- **F-22 P0 跨用户数据越界**（空公共空间 link 抄走全系统 READY 资产）
- **F-11 P1 跨空间静默分叉**（stale 判定从空间归属改为内容指纹）
- R4.8 作业/订阅读面、R4.9.3 OpenAPI 安全标注、生产配置守卫

当前 `knowledge_spaces = 0`，F-22 路径虽可达但无法触发。一旦有空间创建+公开则漏洞立刻可触达。

半迁移态：DB 已有 `content_hash` 列（迁移 `ab1004f11a`），运行中代码不引用。重建会同时改变行为语义（stale 判定方式改变），**旧行为无测试锁定**。

### 选项

| # | 选项 | 风险 | 收益 |
|---|---|---|---|
| A | **授权重建镜像 + 进程复活** | 新代码从未被 L4 验证；行为语义改变无测试锁 | 消除 F-22 在线漏洞；解锁 R6.4 L4 验证面 |
| B | **先补测试锁定旧行为，再重建** | 延迟止血时间；补测试本身也需重建才能验证 | 行为变更可审计 |
| C | **临时下线 link 端点** | 功能退步；仍需重建镜像 | 变更面更小 |
| D | **接受风险，不动作** | F-22 持续在线 | 零成本 |

### 建议
**选项 A**。理由：① F-22 是 P0 数据越界，当前零数据仅是暂态保护 ② 新代码已过 L1/L2 门禁（pytest 551 / ruff / mypy）③ 半迁移态本身就需要对齐，拖延只会加深不一致 ④ 行为语义改变（stale 判定方式）是**正确性修复**，旧行为（按空间归属 stale）才是 bug。

### 关联动作
若批准：立即执行 R6.1.2（重建）→ R6.1.3（复活 scheduler/worker）→ R6.1.4（一致性闸）→ R6.4.1（real-backend e2e 补强）

## 裁定 2：全量历史 vs 仅增量（R6.3.1 · P1 产品口径）

### 背景
当前整号采集受 `DEFAULT_MAX_PAGES=20` 限制，空页即止。老号历史无法补齐。这是**产品口径**而非技术缺陷。

### 选项

| # | 选项 | 成本 | 用户影响 |
|---|---|---|---|
| A | **立项「历史回溯」** | 积分成本显著（100+ 篇老号 × 0.4 积分/篇）；需 `manifest.py` 分页上限可配置化 | 用户可获取全量历史 |
| B | **明确「仅增量」为产品口径** | 零代码成本；需写入需求文档 + 前端提示 | 用户理解仅能同步未来新文 |

### 建议
**选项 B**。理由：① 当前积分=0.0，全量回溯不可执行 ② 增量同步已覆盖 MVP 需求（新文自动入库）③ 全量回溯可在积分充足后作为 M4+ 功能 ④ 明确口径消除不确定性优于含糊的"将来可能"。

### 关联
若选 B：在 `需求文档.md` 追加产品口径说明 + `SubscribeShortcut.tsx` 前端提示。

## 裁定 6：MOCK_ENABLED 默认值（R6.2/C-4 · P2）

### 背景
`frontend/lib/api/http.ts:18` `MOCK_ENABLED` 默认 `true`。生产构建若未设 `NEXT_PUBLIC_API_MOCK=false`，则所有 API 请求走 mock。CI `ci.yml` 无此 env。

### 选项

| # | 选项 | 说明 |
|---|---|---|
| A | **翻转默认为 false** | 生产安全；本地 dev 需显式开 mock 或 prebuild 守卫保护 |
| B | **维持默认 true + CI 强制 false** | 保持 dev 体验；CI 加 env 即可 |
| C | **维持现状** | dev 友好但生产风险 |

### 建议
**选项 B**。理由：① 翻转默认会影响所有本地开发者的首次体验（需要手动设 env 才能看到 mock 数据）② CI 加 `NEXT_PUBLIC_API_MOCK: "false"` 即可解决生产构建问题 ③ prebuild 守卫已存在（`package.json`），CI 补 env 即可通过 ④ 若未来有正式 staging 环境，再考虑翻转。
