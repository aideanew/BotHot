### Why —— 深层原因/动机

1. **为什么单篇通、整号断**：单篇是 M1 验收主链；整号属 M2，其活体验收被 RedFox 账户积分 0.0 卡住。团队按"反造假红线"拒绝 fixture 假成功，把施工半程（骨架/模型/端点壳）建完、活体验收挂起——这是纪律的正确代价，不是工程失败。
2. **为什么无后台管理**：M1/M2 聚焦用户侧 MVP，管理动作（env/SQL/DB 直删）在探针规模下成本可忍；D5 公共库运营一旦开启，"谁有权发布"必须有权限判据——后台从"锦上添花"升级为"安全前置"（D9 已裁 c 过渡 + a 终底）。
3. **为什么无分类**：分类价值依赖内容量（≥100 篇/号）与公共库形态；单篇阶段是过度设计。整号链与公共库进入施工序后，T3.2 到点。
4. **为什么前端两壳页**：引擎路由交付时前端只做了数据层（listEngines/listPublicSpaces 已接），渲染层未完成——"半成品比没有更危险"（加载了数据却看不到），T1.1 收口即此。
5. **为什么组件化欠账**：页面按任务卡独立交付，各页自带 loading/error 手写块；任务卡验收只看本页可用，无人为"跨页一致性"买单，重复度随页面数线性增长。
6. **为什么图片不落盘**：M1 验收口径是文本问答；外链是提取层最小可行实现，防盗链风险在站内渲染场景被低估。
7. **为什么决策点密集（D1~D10）**：产品语义（绑定=检索/归档/来源）无法从代码推导，必须管理者裁决；D1/D2/D5/D9 已落裁，残锁= D10 与 ima 调研（均外部确认项）。

2. 时间锚：2026-09-22；连栈基线止于 09-17（202 passed / 2 skipped）；本轮 Docker 恢复中。

### How —— 执行路径

1. **流程对接**：任务生命周期 = AideanFleet 状态机（DRAFT→ASSIGNED→DOING→SUBMITTED→REVIEWING→DONE/PARTIAL/REWORK/BLOCKED；REWORK×3→ESCALATED）；工作内容 = 六步循环（文档→spec→实现→测试→回写→摘要）；验收权威 = Machine Gate（命令退出码，高于 LLM 自述）。
2. **三波施工序**（脱机并行线洞察）：第一波零依赖（T1 全轨道 + T3）；第二波脱机施工半程（T2.2~2.4 / T2.6 / T2.7 按 `_seed_manifests` 合法种子先例建至"待活体验证"态；T5.0 SPEC 起草；T4.3/T4.4 零代码；T6.1 接线）；第三波解锁后活体（D3→T2.1/T2.5；D6→T7/T8.1；D10→T4.2；Key→T4.1）。
3. **门禁**：后端 pytest（连栈 ≤2 skip）+ ruff + mypy；前端 tsc + vitest + build；compose config；端口铁律；反造假红线；密钥零明文。
4. **证据纪律**：每原子任务验收锚 + file:line 证据锚；无 transcript 不判 DONE；台账随任务即时更新。

### What if —— 前提变了会怎样

1. **D3 积分长期不到位**：T2 施工半程照常推进；风险=RedFox API 形状漂移致解析层返工——返工面隔离在 client.py 防腐层内。更坏：RedFox 停服 → 目标 2 降级"仅单篇"，产品回 M1 形态。
2. **D6 Docker 持续离线**：连栈复验债滚存；68 skip 用例真实质量未知期延长；N13 真实态 e2e 无法落地。
3. **用户推翻 D1=A**：T4 轨道重排（语义 B → Notion 导出先行）；返工面=SPEC 层，零代码损失（引擎位骨架通用）。
4. **整号完成后文章量超预期**：ContentAsset 全局缓存成为热点（hit_count 已预埋）；worker 可水平扩展（SKIP LOCKED 设计已预留）；需补 T1.5.7 分页统一（v1.1 已立）。
