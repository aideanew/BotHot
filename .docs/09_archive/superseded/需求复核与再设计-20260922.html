01

结论速览

Verdict

产品按"单篇采集问答 MVP"成立且经真实活体验证（ingest 202 → 5 秒 READY → SSE 带真实引用）； 按《需求文档》目标 2（整库 / 单篇二选一）与目标 3（主动推送）仍欠半壁。四个硬缺口经拷问后判定全数维持：

已成立单篇 MVP 主链

单篇采集 → 入库 → 检索 → 问答全链闭环，SSO 免二次注册、幂等五层、脱机门禁全绿。 证据：09-13 活体终验（202→5s READY→SSE 帧序 meta/citations/delta×12/done）；pytest 定向 53 passed、vitest 9 文件 89 用例。

壳在待通四大硬缺口

① 整号采集闭环——端点在、执行链断（无 worker / scheduler），且被 RedFox 积分 0.0 卡住活体； ② 后台管理——零 admin 端点、users 表无 role 列（M3 全量已裁，待 SPEC）； ③ 外部知识库绑定——仅 builtin 引擎可用，Coze / Dify / FastGPT 共 12 方法未实接； ④ 分类体系——零字段、零 UI。

待补强三类质量项

前端两壳页（/engines、/public 各 36 行，加载不渲染）与全局兜底页缺失；组件化欠账 （巨石组件 651 行、api.ts 1213 行、loading/error 多份重复）；图片仅存外链、防盗链未实测（D4 先验证后改码）。

立即开工窗口（零外部依赖）：T1 全轨道（前端收口 / 组件化 / 公共库一期 / 技术债）+ T3（检索质量续 + 分类）。 其余轨道按"脱机施工半程 → 解锁后活体"推进，依赖锁见 §06。

前提与局限

Limits
  1. 判定基于 HEAD 5b17da2 + 工作树实测（2026-09-22 15:0x）；若后续代码演进，以可运行代码为准回写。
  2. 连栈口径（202 passed / 2 skipped）自 09-17 未复跑；本批 Docker 起栈窗口中，连栈复验由恢复后的对应批次执行——本页不据此宣称"连栈绿"。
  3. 本批 3 路独立核验 Agent 因环境 LLM 故障全部中断（含 1 次重试）；全部核验面由主线逐项补位完成、判定零翻案，但"独立第二源"证据强度低于前几轮（C6 如实登记）。
  4. RedFox API 响应形状以活体为准（当前以 mock 单测锁定形状）；T2.1.1 活体时如形状漂移，返工面隔离在防腐层内。
  5. T5（M3）/ T4.3（飞书扩槽）启动须走 SPEC → APPROVE；本页不构成对并行实施批次成果的验收。
