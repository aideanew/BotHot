# 评审报告：两份开发计划交叉裁决

> 版本：v1.0 | 日期：2026-09-04 | 评审方：TRAE（持 M0 活体实证）
> 评审对象：`.docs/立项分析/开发计划_WorkBuddy.md`、`.docs/立项分析/开发计划_OpenCode.md`
> 评审方法：两份计划均为**静态源码审计**（均自声明"未启动任何进程"）；本项目 M0 已完成**活体实证**（LangBot 全链 / SSO 六步 / 网关双墙 / 多库隔离 / Redfox 契约 / wandao 移植 83%）——**凡静态结论与活体证据冲突者，以活体为准**。
> 采纳产出：ADR-0003 新建、ADR-0002 增补、compose/env 网络与嵌入服务修订、M1 任务增量（见 §五）。

## 一、总体评价

| 维度 | WorkBuddy | OpenCode |
|---|---|---|
| 方法论 | 三轮自我纠错（撤 4 条自身断言），诚实度高 | 源码反证（6 条推翻），证据链扎实 |
| 独有贡献 | openclaw-weixin 适配器发现（E6）、会话→空间规则空洞（Q2）、A7 方向纠错 | 双轨鉴权发现（/bots HMAC vs lbk_）、MALFORMED_URL 分支、每空间 bot+pipeline 方案推荐 |

| 共同盲区 | 网络工程现实（代理/镜像）、嵌入模型必填、M0 已完成的前提失效 | 同左 |

| O5 | T0.0.4：ADR-0000 推翻 docx §3.2 | ❌ 驳回 | WorkBuddy 第二轮已自证方向搞反（docx §3.2 与 V2 §三十八 实际一致） |
| O6 | Q2：会话→空间解析规则缺口 | ✅ 采纳 | 同 W7 → ADR-0003 |

## 四、两份计划共同盲区（活体实证补充）

1. **嵌入模型必填**（两份均未发现）：建库强制 `creation_settings.embedding_model_uuid`，ingest 每批强制嵌入——没有嵌入服务连 KB 都建不了。在用户"本地不部署大模型"约束下，M1 前置任务 T1.0.1 = 配置 API 嵌入服务（默认推荐硅基流动：国内直连、OpenAI 兼容、bge 系列低价；env 可配可换）。
2. **网络工程现实**（两份均未涉及）：宿主代理注入坑（127.0.0.1 死代理）、pip `-i` 硬编码、Docker Hub 国内受限。今日实测（2026-09-04 下半场）：**10808 端口开放且 HTTP/SOCKS5 双协议可用；直连国外不通；10809 已关闭**（与 M0 时状态翻转）。
3. **M0 已完成**：两份计划以"M0 待执行"为前提，其 M0 任务大多已执行有结论；增量价值重新定位为 M1 输入。

## 六、局限性声明

- HMAC 签名与"每空间 bot+pipeline 编程创建"两条仍是静态推断，其活体验证本身即 M1 T1.10 首个任务——本评审将其从未知提升为"已排队待验证"。
- 10808 代理可用性基于今日实测；代理软件关闭时系统依赖分层规范中的镜像层仍可运作（设计上抗代理失效）。
- 嵌入服务默认推荐基于三要素（国内直连/OpenAI 兼容/低价），最终选择权在用户（env 可配）。
