### 2. Why（深层原因/动机）

1. **文档超前于验证闭环**：R4 v1.3 以「转述数字 + 静态证据」宣布 R5 竣工，但竣工验收标准（页面级断言、CI lint、prebuild 可运行）未逐条以 L2 复跑坐实 → 形成「账面竣工、实测有洞」。
2. **测试金字塔中层（page-level）与流水线门禁被后置**：开发期优先 API/组件级 fast feedback，page 级与 CI lint 属「应然门禁」而非「阻塞修 bug」，故被系统性挤出批次。
3. **回写纪律弱于实现纪律**（R4 根因 4 的延续）：CANCELLED 已入 `batch.ts` 但 API 文档 :1044 历史句未追加更正注；台账 §41.5 行数未按 §五 实测回刷。
4. **外部凭据缺位**把「活体 L4 验收」与「引擎实接」结构性推迟，但**不解释** G1~G4、G7、G10、G11 这些零依赖缺口为何仍在。

## 第二轮 · 苏格拉底拷问 + 双向钢人

### 对 What 的拷问

**Q1：G1 是否真的未验收，还是「断言写在别处」？**
- 钢人正方：可能断言在集成层或 e2e。
- 钢人反方：R4.7.1/4.7.2 验收判据明确写「`r11-admin-console.spec.tsx` 新增断言」；对该文件 grep 两符号皆 No files found。函数存在 ≠ 验收通过。
- **存活结论**：G1 成立，验收判据未达。

**Q2：G2 的「page 级」与既有 API spec 是否重复建设？**
- 钢人正方：API+组件已覆盖行为，page 级边际价值低。
- 钢人反方：R4.5.4 验收明文「每页 ≥1 spec」；`/`、`/chat` 连组件级冒烟都无独立 page 文件，路由挂载/布局回归无锁。
- **存活结论**：G2 成立，但实施时应「薄 page 冒烟」而非复制 API 断言。

**Q3：G3/G4 是同一问题还是两个？**
- 钢人正方：都是 ci.yml 缺配置，应合并。
- 钢人反方：G3 = 缺 lint **步骤**（质量门禁）；G4 = 缺 env 导致 prebuild **可能失败或守卫失效**（构建正确性）。修复动作不同（加 step vs 加 env/改守卫策略）。
- **存活结论**：拆为两原子，可同一 PR 修。

**Q4：G9「有意不做」是否应从待办剔除？**
- 钢人正方：R5 已裁定冗余，应销账。
- 钢人反方：R4 原文仍要求 `GET /admin/sources`；口径冲突需管理者显式确认「维持不做」并回写 R4 大纲注记，否则后人按 R4 复工。
- **存活结论**：保留为「裁定确认+回写」任务，非编码任务。

**Q5：G11 是否违反「历史不覆盖」？**
- 钢人正方：:1044 是历史，:1078 是更正，已并存，无需动。
- 钢人反方：纪律是「追加更正注」而非「留一个无指针的矛盾」；读者读到 :1044 会以为仍待办。需在 :1044 尾部追加「（更正：已于 :1078 / R0.4.3 销账）」。
- **存活结论**：G11 = 追加更正注，非删除。

### 对 Why/How 的拷问

**Q6：为何不把 G5 与外部锁合并成一项？**
- 钢人正方：都等 Compose+OIDC。
- 钢人反方：G5 还可先做「骨架结构校验 job」（不起栈，仅 lint spec 结构与 config 分 job 说明），与真跑解耦。
- **存活结论**：拆「结构可跑」与「真栈 L4」两原子。

**Q7：施工序是否应 P0 安全优先（SSO）而非测试债？**
- 钢人正方：安全 > 测试。
- 钢人反方：R5.1 SSO iss/aud 校验按 R5 大纲已列且 OIDC 配置项已存在；本终稿聚焦「v1.3 声称竣工但实测有洞」的差异集。SSO 若 R5.1 已落地则不在本差异集；若未落地应单列复核。
- **存活结论**：本终稿主清单 = **实测差异集**；SSO 作为独立 P0 复核项列入（若 service.py 尚无 `_verify_userinfo_claims` 则立即升 P0）。
